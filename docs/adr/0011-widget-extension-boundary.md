# ADR-0011. Граница расширения Control Plane: виджеты и отчёты

- Статус: предложен
- Дата: 2026-10-05
- Пункты ТЗ: §12 (преамбула), §12.1, §12.2, §12.3, §11 («generate
  report/widget data через read-only contracts»), §17.5 (четыре последних
  пункта), §18 Phase 7 п. 7 и Phase 8, §15.2 («утечка через widgets»,
  «случайный публичный доступ Control Plane»), §22.7, §21 п. 11
- Связан с: [ADR-0001](0001-sqlite-ledger-authority.md),
  [ADR-0003](0003-revisions-conflicts.md),
  [ADR-0009](0009-mcp-authorization.md),
  [ADR-0012](0012-adopted-components.md), `docs/threat-model.md` п. 7 и п. 11,
  план: волна 8 (Т8.0–Т8.7), раздел 2 (решение владельца 2026-10-05), М5 п. 13

## Контекст

Control Plane обязателен — решение владельца 2026-10-05 (план, раздел 2).
Строить его нельзя раньше закрытия волны 2 (§22.7: не над нестабильной
моделью авторитета), а по М5 п. 13 — после волны 5. Кода нет: ни `web/`, ни
`package.json`. То есть этот ADR пишется **до** первой строки и фиксирует
границу, а не описывает существующее — единственный такой из двенадцати.

Что при этом уже решено и чего граница не вправе нарушить:

- Власть — реестр, писатель карточек один, обходного SQL API для агентов
  нет (ADR-0001, ADR-0009 решение 8). §4.1 перечисляет «позволять UI, MCP,
  агенты или source adapters писать в обход доменного write API» среди
  запрещённого.
- Единственная доменная мутация сегодня — `correction` через
  `check_correction` → `apply_correction`; `expected_version` и `409` — по
  ADR-0003, ещё не сделаны. Control Plane по §12 использует **тот же** domain
  API и те же правила параллелизма, что MCP и правки.
- Чувствительное наружу не идёт: `/metrics` только с петли, `last_error`
  только с петли (ADR-0009), логи без транскриптов (§15.1).
  `threat-model.md` п. 7 называет виджеты каналом утечки наравне с логами и
  бэкапами, п. 11 — требует, чтобы Control Plane слушал только петлю и VPN
  и без входа не отвечал; это первый критерий закрытия Т8.1.
- Токены устройств имеют allowlist видов событий (`contextd.scope_ok`) —
  это права на **запись**; прав на чтение в системе нет ни у кого, кроме
  «опознан — читай всё».

Что сегодня играет роль панели: дайджест в телеграм (`call_digest`), сводка
сверки, утренний список (`mara-brief.py`, `docs/morning-brief.md`), Obsidian
над проекцией и `/metrics`, который никто не читает (аудит §17.5: минус
единица в метрике три недели не замечали). Все пять — чтение; ни одно не
правит обязательство с проверкой версии.

§12.2 даёт манифест виджета (`id`, `version`, `title`, `data_contract`,
`permissions`, `refresh_policy`) и восемь правил; §12.3 — ориентир стека
(React + Vite, TanStack Query, OTel — при соответствии стеку, без крупного
фреймворка ради моды), окончательный выбор — за `RES-OSS-001` (Т8.0).
§18 Phase 8 относит сторонний plugin SDK к измеренным расширениям, то есть
MVP — встроенный реестр.

## Решение

**1. Граница проходит по контракту данных, а не по компоненту интерфейса.**
Единица расширения — *контракт*: именованный, версионированный, только для
чтения запрос, реализованный **на сервере** в коде репозитория
(`mara.report.<имя>.v<N>` по образцу §12.2). Виджет и отчёт — потребители
контракта. Ядро владеет контрактами и исполняет их; расширение владеет
отрисовкой и ничем больше.

**2. Что виджет может.** Читать данные только через объявленный в манифесте
`data_contract`, через HTTP-роут `contextd` или через MCP-инструмент того же
имени — §11 требует, чтобы отчётные данные для агентов шли через те же
read-only контракты, значит контракт один, потребителей два. Ответ
ограничен по размеру и по времени на сервере (§12.2 «bounded response/
time»); пагинация — часть контракта, не виджета. Виджет объявляет
`refresh_policy`, сервер вправе её огрубить.

**3. Что виджет не может — и это проверяется на сервере, не на совести
автора.** Не читает SQLite, файлы под `MARA_BLOBS`, волт, `/etc/mara`. Не
имеет собственного токена: данные ему отдаёт оболочка панели под сеансом
владельца. Не отправляет ничего во внешнюю сеть ни с клиента, ни через
сервер — контракт не принимает URL. Не пишет в реестр: у контракта нет
мутаций по построению. Произвольного SQL, фильтра-выражения или языка
запросов в контракте нет; параметры — закрытый список с типами (§12.2 «no
arbitrary SQL», §17.5 последний пункт).

**4. Действие из виджета — это доменная команда оболочки, не виджета.**
Кнопка «закрыть обязательство» на виджете вызывает **ту же** команду, что
`mara_correction` и будущие команды §4.6 (переходы `done`, `cancelled`,
`superseded`, перенос срока): с `expected_version`, актором `human` и
строкой `audit_events`. Виджет лишь просит оболочку выполнить команду по
имени; `409` показывает оболочка (UX конфликта — Т8.3), и виджет его не
перехватывает. Это §12.2 дословно: «не могут менять каноническое состояние
без отдельной domain action».

**5. `permissions` манифеста — это read-scopes, и их в системе ещё нет.**
§12.2 пишет `["health:read"]`, но ни ТЗ, ни ADR-0009 модели прав на чтение
не задают: сегодня опознанный токен читает всё, а колонка scopes у
устройств — про виды событий на запись. Решение: контракт объявляет
требуемый read-scope; оболочка панели выдаёт сеанс владельца со всеми
scopes; MCP-клиент получает подмножество по политике ADR-0009. Минимальный
словарь на старте — четыре: `health:read` (дашборд, очереди, узлы,
бэкапы), `memory:read` (объекты без текста evidence), `evidence:read`
(текст сегментов и фрагменты аудио), `observatory:read` (прогоны агентов).
Контракт, отдающий текст расшифровки, тело сообщения или письма, живёт
только под `evidence:read` и только с петли/VPN — это та же граница, что у
`last_error` в ADR-0009. Контракты `health:*` обязаны быть безопасны для
общего экрана (§12.1 «без утечки чувствительного текста»): в них нет имён
контактов, номеров и текста.

**6. Регистрация — встроенный реестр в репозитории, изменения через PR.**
Манифест и код отрисовки лежат рядом с панелью; список зарегистрированных
виджетов — часть сборки, а не загрузка во время работы. Виджет без строки в
реестре не отрисовывается; контракт без реализации на сервере не
регистрируется. Сторонний SDK с загрузкой кода извне — Phase 8, со своим
ADR, бенчмарком и путём выхода; до него «плагин» значит «каталог в нашем
репозитории под нашим ревью».

**7. Версионирование контракта — аддитивно внутри версии, новая версия —
новый суффикс.** В `v1` можно добавить поле, нельзя убрать, переименовать
или сменить тип (то же правило, что у манифеста пакета в ADR-0008).
Несовместимое — `v2` рядом, `v1` живёт ещё один релиз панели. Виджет
объявляет точную версию; отсутствие контракта на сервере — не ошибка панели,
а состояние виджета «недоступен» с причиной (§12.2 «graceful degradation»).

**8. Что ядро, что расширение.** Ядро: оболочка PWA (вход, сеанс,
маршрутизация, UX конфликта, вызов команд), реестр, все контракты и их
серверная реализация, доменные команды. Расширение: любая отрисовка
read-only данных, включая **первопартийные разделы §12.1** — дашборд,
очереди, рекордер, бэкапы, Agent Observatory пишутся как виджеты над теми же
контрактами. Это не стилистика: если наш собственный дашборд не умещается в
границу, граница неверна, и узнать это надо на своём коде, а не на чужом.
Мутирующие экраны (Commitments: create/edit/complete, merge/split алиасов)
— ядро, потому что они вызывают команды.

**9. Сеть.** Панель слушает петлю и VPN, без входа не отвечает
(`threat-model.md` п. 11). Виджет этого не знает и знать не должен —
граница сети у оболочки.

## Альтернативы

- **Read-only SQL для виджетов** («всё равно только чтение»). Отвергнуто
  §12.2 и §11 прямо; кроме того, read-only не значит безвредно: `select text
  from transcript_segments` — это утечка п. 7 модели угроз одним запросом.
- **Универсальный язык запросов (GraphQL, фильтры-выражения).** Один
  контракт на всё, зато неограниченная стоимость запроса и невозможность
  сказать заранее, какие поля уедут на общий экран. Отвергнуто: контрактов
  будет десяток, и каждый дешевле схемы запросов.
- **Виджеты как iframe со своим бэкендом (plugin SDK сейчас).** Это Phase 8;
  без модели прав на чтение (решение 5) SDK раздавал бы либо всё, либо
  ничего. Отвергнуто до измеренной потребности.
- **Grafana или подобное над `/metrics` вместо дашборда.** Закрывает один
  раздел из семи и ни одной мутации; внешний компонент со своим ADR-0012.
  Не отвергнуто навсегда — как читатель метрик он границе не противоречит,
  но Control Plane он не заменяет.
- **Obsidian и телеграм как панель навсегда.** Это сегодняшнее состояние;
  ни правки с `expected_version`, ни очереди ревью `409`, ни экрана
  восстановления рекордера оно не даёт. §12 и владелец сказали «обязательно».
- **Один токен на все контракты без scopes.** Проще на старте и ровно тот
  сценарий §15.2 «утечка через widgets», в котором виджет здоровья получает
  текст расшифровки. Отвергнуто.

## Последствия

- У каждого контракта два потребителя — панель и MCP — и одна реализация;
  это дисциплинирует: поле, которое нельзя показать агенту, нельзя показать
  и виджету.
- Появляется модель прав на чтение, которой в системе не было. Она
  затрагивает ADR-0009 (там scopes — только про запись) и будущие
  MCP-контракты Т6.3; делать её надо до первого виджета, не после.
- Мутации из панели упираются в Т2.3 (`expected_version`) — поэтому и
  порядок «после волны 2» не формальность: без версии кнопка «закрыть» в
  панели была бы тем же last-write-wins, который ТЗ запрещает.
- Первопартийные разделы как виджеты — лишний слой ради проверки границы.
  Цена — манифесты и реестр для своего же кода; выигрыш — граница, которая
  проверена до появления первого чужого виджета.
- Стек по §12.3 выбирается в Т8.0 с карточкой ADR-0012 на каждый пакет;
  этот ADR стек не фиксирует и от него не зависит.
- Телефон как клиент панели — только через VPN (решение 9); §12 обещает
  «desktop/mobile browser», и это обещание выполняется с оговоркой, которую
  надо записать в руководство.

## Откат и миграция

Мигрировать нечего — данных у виджетов нет по построению, и это главное
свойство границы: удаление любого виджета или всего реестра не теряет ни
строки реестра, контракты остаются (их читает MCP). Откат отдельного
контракта — снять роут и инструмент; виджеты над ним переходят в
«недоступен» без правок.

Если граница окажется слишком тесной — виджету понадобится соединение,
которого ни один контракт не даёт, — ответ один: новый контракт через PR, с
реализацией на сервере и объявленным scope. Дырка «временно дадим SQL» не
предусмотрена ни в одном шаге, и это единственное в ADR, что не
откатывается: открытый однажды обходной путь к базе ревью обратно не
закрывает (ADR-0009 про Basic Memory — пример того, как это выглядит).

Если Phase 8 принесёт сторонний SDK, он ложится **поверх** этой границы:
тот же манифест, те же контракты и scopes, добавляется лишь способ доставки
кода. Контракты `v1`, объявленные до него, не меняются.
