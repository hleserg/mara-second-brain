# ADR-0013. Извлечение фактов из звонков — облачной моделью

- Статус: принят 2026-10-19 (решение владельца)
- Дата: 2026-10-19
- Пункты ТЗ: `TZ-master.md:550` («аудио и полные транскрипты не отправлять
  в стороннее облако без отдельного явного решения») — этот ADR и есть
  такое решение для транскриптов; §7.3, §13.1, §17.5
- Заменяет: [ADR-0012](0012-adopted-components.md) строку реестра «Ollama
  (Big PC)» и п. 3 путей выхода («заменять облаком нельзя»);
  [ADR-0010](0010-compute-scheduling.md) решение 1 в части модели
  (`node_no_model`)
- Связан с: `docs/threat-model.md`, `scripts/call_extract.py`,
  `scripts/contextd.py` (`РАБОТЫ`)

## Контекст

`call_extract.py` доставал просьбы и обещания из расшифровки звонка
локальной моделью `qwen3.5:9b` в ollama на bigpc — только ради того, чтобы
полные транскрипты не уезжали в чужое облако. Цена этого: извлечение
работает, только пока bigpc включён, не играет и держит модель в памяти;
doctor сверяет список моделей узла (`node_no_model`), прокси узла
подписывает запросы к ollama; точность локальной модели на корпусе Т5.5 —
0,7 (`python3 scripts/extract_eval.py --live` на doctor, PR #185). Точность
облачной модели ещё не измерена — тем же прогоном после выката.

Владелец снял условие приватности для звонков явно: «пофиг на приватность,
пусть GPT делает».

## Решение

1. **Модель извлечения — облачная, через OpenRouter.** По умолчанию
   `openai/gpt-6-luna` (`vault_common.МОДЕЛЬ_ИЗВЛЕЧЕНИЯ`), переопределяется
   `MARA_EXTRACT_MODEL`; адрес — `MARA_EXTRACT_API` (по умолчанию
   `https://openrouter.ai/api/v1`), ключ — `OPENROUTER_API_KEY`, тот же,
   что у `queue-worker` и `daily-summary`.
2. **Транскрипт уходит целиком и без редакции.** Имена людей — это и есть
   извлекаемые данные; цепочка редакции §8.3 `TZ.md` их бы вырезала.
   Вместе с расшифровкой в системном промпте уходит имя владельца
   (`MARA_OWNER_NAME`, если задано, — по нему модель отличает его реплики);
   в происхождение ревизии пишется только флаг `owner_named`.
   Аудио по-прежнему не уходит никуда: расшифровка остаётся на bigpc.
3. **Схема ответа — `response_format: json_schema` без `strict`.** Строгий
   режим требует, чтобы все ключи были обязательными, и модель стала бы
   заполнять `owner`/`supersedes` там, где их нет. Нормализация и
   валидация в `call_extract` остаются прежними. `provider.require_parameters`
   не даёт OpenRouter увести запрос к провайдеру без структурного вывода.
4. **Промпт — системным сообщением, расшифровка — пользовательским**,
   `temperature: 0`; `PROMPT_VERSION` поднят до 4, поэтому старые и новые
   ревизии извлечения различимы по происхождению. `RULES_VERSION` прежний.
5. **Работа `extract` — лёгкая, на doctor.** У неё в `РАБОТЫ` больше нет
   узла, возможности и модели: застава игры, сердцебиение bigpc и проверка
   моделей её не держат. Механизм `node_no_model` удалён целиком — он был
   нужен только этой работе. Поле `models` в сердцебиении агента осталось
   частью протокола: агент на bigpc уже развёрнут, а doctor его по-прежнему
   разбирает.

## Последствия

- Извлечение работает, когда bigpc выключен; тяжёлым остаётся только `asr`.
- Полные транскрипты звонков и имя владельца уходят OpenRouter и провайдеру
  модели. Это принятый владельцем риск; запись в `docs/threat-model.md`.
- `OPENROUTER_API_KEY` теперь нужен contextd на doctor (`~/.config/mara/env`
  пользователя сервиса): без него извлечение уходит в ретраи и DLQ.
- Каждый звонок стоит денег — по тарифу OpenRouter для выбранной модели.
  Нет ключа — `call_extract` падает с понятной ошибкой, работа уходит в
  ретраи и DLQ, как при любом отказе шага.
- Ollama на bigpc больше не нужна и выключается. Ollama на doctor с
  `bge-m3` остаётся: её использует Basic Memory.
- Живой прогон корпуса (Т5.5) теперь — с облачной моделью:
  `python3 scripts/extract_eval.py --live --record` на doctor, нужен
  `OPENROUTER_API_KEY`.

## Путь выхода

Смена модели — `MARA_EXTRACT_MODEL`; смена провайдера на любой
OpenAI-совместимый `/chat/completions` (в том числе локальный, если
приватность снова понадобится) — `MARA_EXTRACT_API`.
