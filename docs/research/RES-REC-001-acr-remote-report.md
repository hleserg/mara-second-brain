# RES-REC-001 — «Отчёт на удалённый сервер» ACR Phone (Server + Secret)

- Статус: кабинетная часть — 2026-10-14; полевая — зондом, владелец (мешок М4).
- Вердикт сейчас: **experiment only** (ТЗ §7.3: `adopt`, `experiment only` или `reject`).
- Пункты ТЗ: §7.3, §20 `RES-REC-001`, §17.2 («`Server + Secret` не назван webhook»), §22 п. 10.

## Вопрос

Что на самом деле делает раздел «Отчёт на удалённый сервер» с полями
**Server** и **Secret**?

§20 требует ответить на десять вопросов:
- протокол и метод;
- payload;
- auth/signature;
- TLS;
- повторы;
- доставка файла записи;
- таймаут;
- идемпотентность;
- поведение в фоне и после перезагрузки;
- вердикт.

Пока ответа нет, слово «webhook» о нём как о факте не используется.

## Источники

1. **Справка производителя «Call Reporting»** —
   `https://nllapps.com/apps/cb/help-call-reporting.htm`. Из облачного
   окружения агента сайт не открывается: DNS-имя закрыто сетевой политикой.
   Поэтому ниже — пересказ по выдержкам поисковой выдачи 2026-10-14, а не
   цитата. Что в них:
   - отчёт — продвинутая функция, включается в её настройках;
   - адрес своей страницы или службы, принимающей данные формы, вписывается
     в Server в настройках записи звонков;
   - после каждого звонка уходит запрос — по опциям, выбранным в настройках
     отчёта;
   - успех — ответ 200; на 401 или 404 приложение само выключает отчёт и
     показывает уведомление;
   - образцов серверного кода для отчёта нет: отчёт «очень похож на клиент
     WebHook облачной службы», образцы которого есть на .NET Core и PHP.
2. **Пример сервера WebHook от производителя** — `github.com/NLLAPPS/acrphonewebhook`,
   коммит `3f95d84` (2026-09-09), лицензия GPL-3.0. Прочитан, код не
   заимствован. Что в нём (`Controllers/RecordingController.cs`, метод
   `Upload`, и `ViewModels/UploadRecordViewModel.cs`):
   - приём — `POST /api/recording/upload`, `multipart/form-data`;
   - поля:
     - `Source` — обязательное;
     - `File` — файл, необязательный;
     - `FileName`;
     - `Secret` — обязательное;
     - `Date` — целое, сервер читает как секунды эпохи;
     - `Duration` — целое, сервер показывает как миллисекунды;
     - `Note`;
   - секрет сравнивается на равенство с настроенным; не тот — 401. Пустой
     секрет пример пропускает — это промах примера, а не протокол;
   - ответы: 200 — принято, 400 — файл в 0 байт, 500 — сбой сохранения.
3. **Политика приватности NLL**: приложение само ничего не передаёт ни
   производителю, ни третьим лицам — только туда, куда настроил владелец.

## Что из этого следует для архитектуры

- **Это не подписанная доставка.** Секрет — общий пароль в теле запроса:
  без подписи и без защиты от повтора. По HTTP внутри сети его видит
  любой, кто слушает. Принимать такое можно только по HTTPS или через туннель.
- **Наш приёмник не может отвечать 401 или 404 на временные беды.** Иначе
  отчёт выключится молча для doctor — уведомление увидит только телефон.
  Временное — 5xx или 503, дубль — 200.
- **Если отчёт везёт файл,** он может стать вторым провайдером записи
  (ADR-0007: провайдеры по способу доступа — «доставка самим рекордером»)
  рядом с медиатекой и папкой. Запись уходила бы с телефона, даже если
  приложение Мары выгружено. Но после перезагрузки он не надёжнее самого ACR
  (§7.2): reboot-unsafe он не снимает.
- **WebHook облачной службы** — отдельная функция ACR. Это кандидат
  `RES-REC-002` («способы передачи», Т4.6); тот же зонд снимает и её.

## Вердикт

**experiment only.** Производственный приём на «Отчёте на удалённый сервер»
не строится, пока зонд не ответил на пять вопросов:
1. везёт ли отчёт файл;
2. какие поля и в каких единицах;
3. повторяет ли при 5xx;
4. какой таймаут;
5. уходит ли отчёт после перезагрузки, не открывая ACR.

После полевой записи вердикт пересматривается: при `adopt` — ADR о новом
провайдере, иначе — `reject` с причиной.

## Зонд и полевая проверка

**Зонд** `scripts/acr_report_probe.py` — контролируемая точка приёма из §20.
Он принимает любой запрос и пишет в журнал (`~/.local/state/mara/acr-probe.jsonl`,
права 0600) только форму запроса, без содержания:
- поля формы — имя, длина и форма значения: цифры — `9`, буквы — `a`.
  Номер, имя и заметка в журнал не попадают;
- дату и длительность — как есть, чтобы были видны единицы. Номер телефона
  в окно «метка 2020–2033 годов» не попадает;
- секрет — только длина и совпадение с `--secret`;
- у файла — тип, размер, sha256 и первые байты (по ним виден формат).

Тело на диск не ложится без `--keep`. Ответ зонда задаётся флагами:
- `--status` — код ответа;
- `--delay` — задержка ответа.

Шаги для владельца — `docs/USER-MANUAL-STEPS.md`, раздел «Исследование
отчёта ACR на сервер». Журнал зонда номеров и имён не содержит — его можно
прислать агенту целиком.
