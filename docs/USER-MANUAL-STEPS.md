# Что придётся сделать руками

Здесь только то, чего агент сделать не может: нажатия на телефоне, пароли,
разрешения. Всё остальное уже стоит и работает.

Состояние на 2 сентября 2026: `contextd` поднят на doctor, релей на маке
слушает `100.64.0.1:8788`, крон сверки и уборки прописан. Контекст-брокер
собран и проверен на живом маке: плагин `mara-context` включён в Hermes, ходит
через релей и отвечает за 0,08 с. Приложения на телефоне ещё нет — это
следующая спека.

## 1. Ключ релея на doctor (одна строка, две минуты)

Релей сейчас ходит на doctor обычным ключом мака, который может там всё.
Для форварда этого много. На маке уже лежит отдельный ключ `~/.ssh/id_mara_relay`,
осталось разрешить ему только проброс порта. На doctor:

```bash
umask 077
printf 'restrict,port-forwarding,permitopen="127.0.0.1:8788" %s\n' \
  "$(ssh mac-mini cat ~/.ssh/id_mara_relay.pub)" >> ~/.ssh/authorized_keys
```

Потом в `~/Library/LaunchAgents/com.mara.relay.plist` на маке добавить к
аргументам `ssh` строки `-i` и `~/.ssh/id_mara_relay`, и перезапустить:

```bash
launchctl kickstart -k gui/$(id -u)/com.mara.relay
curl -s http://100.64.0.1:8788/healthz
```

Скомпрометированный телефон после этого не сможет выполнить на doctor ничего,
кроме проброса одного порта.

## 2. Автовход на маке

Релей — это агент launchd в GUI-домене: он стартует при **входе в систему**, а
не при загрузке. Если мак перезагрузится и никто не залогинится, телефон будет
лить записи в никуда. Либо включить автовход в «Пользователи и группы», либо
помнить об этом после каждого выключения света.

## 3. Телефон

Появится в следующей спеке, но порядок такой:

1. Разрешить установку из неизвестных источников и поставить APK.
2. Выдать разрешения: доступ к папке записей, журнал звонков, контакты,
   работа в фоне без ограничений батареи.
3. Забрать токен устройства — он показывается **один раз**:

   ```bash
   ssh doctor 'python3 ~/mara-second-brain/scripts/contextd.py --pair phone'
   ```

4. Сделать один тестовый звонок себе и убедиться, что в телеграм пришёл
   дайджест. Если не пришёл — `ssh doctor 'journalctl -u contextd -n 50'`.

## 4. Индекс Copilot в Obsidian

На **каждом** устройстве с волтом добавить `kb/conversations`,
`kb/commitments` и `_system/context` в исключения индекса Copilot. Без этого кнопка Index vault
отправит расшифровки разговоров в облако — мимо всех проверок, которые здесь
написаны, потому что индексирует плагин, а не наши скрипты.

Там же: не нажимать Index vault, пока исключения не выставлены.

## 5. Что важно знать

- **Записи звонков хранятся 90 дней** в `/srv/mara-blobs`, потом удаляются
  сами. Манифест остаётся навсегда. Чтобы запись жила вечно:
  `sqlite3 /srv/mara-blobs/contextd.db "update blobs set pin=1 where sha256='...'"`.
- **bigpc включён не всегда.** Лестница повторов растянута примерно на 14,5
  часов. Звонок, записанный пока коробка выключена дольше, уедет в DLQ, и его
  придётся вернуть в очередь руками. Сверка сообщит о таком раз в час.
- **Мара видит открытые обязательства без вызова инструмента.** Список
  собирается в `_system/context/now.md` и приезжает в её ход через плагин. Пока
  ни одного звонка не разобрано, список пуст и в ход не едет ничего. Проверить,
  что она их видит, можно будет после первого настоящего звонка: спроси её, что
  ты кому обещал, — она должна ответить сразу, не идя в basic-memory.
- **Токен плагина** лежит в `~/.hermes/.env` на маке как `MARA_CONTEXT_TOKEN`,
  устройство `mara-hermes` в базе contextd. Отозвать:
  `ssh doctor 'python3 ~/mara-second-brain/scripts/contextd.py --revoke dev_0000000000000000'`.
- **Аудио никогда не попадает** ни в волт, ни в git, ни в R2: блобы лежат вне
  дерева волта. Проверяется тестом, а не обещанием.
