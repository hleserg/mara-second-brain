# Учёт расхода лимитов Claude Code

Состояние на 2 сентября 2026. Собраны все семь этапов брифа. Часть приёмки
§11 упирается не в код, а в время: калибровать веса и увидеть сброс недели
можно только на накопленных данных.

## Что выяснила разведка

Бриф исходил из того, что данные придётся собирать хуками. Оказалось, почти
всё уже лежит в транскриптах `~/.claude/projects/<проект>/<сессия>.jsonl`:

| Запись | Что несёт |
|---|---|
| `assistant` | `message.usage` (вход, выход, запись и чтение кэша, `output_tokens_details.thinking_tokens`, `cache_creation.ephemeral_1h/5m`), `message.model`, `message.id` (ключ дедупа), `timestamp`, `effort`, `version`, `cwd`, `gitBranch`, `isSidechain` (подагент), `advisorModel`, `attributionSkill` |
| `assistant.message.content[]` | блоки `tool_use` — имя инструмента, MCP-сервер по префиксу `mcp__<сервер>__` |
| `user.toolUseResult` | результат инструмента целиком, отсюда его размер в байтах |
| `system.compactMetadata` | компакции: `trigger`, `preTokens`, `postTokens`, `cumulativeDroppedTokens`, `durationMs` |
| `cost-state` | `totalCostUSD`, `modelUsage` с токенами и `costUSD` **по каждой модели**, `hasUnknownModelCost`, длительности, строки кода |

Отсюда два вывода, которые сократили работу:

- **Хуки не нужны вовсе.** Ни `PostToolUse`, ни `SessionStart`, ни `PreCompact`.
  Всё, что бриф просил собирать хуками, уже в транскрипте, а транскрипты на
  doctor приносит существующий `SessionEnd`-хук — 535 файлов в
  `raw/claude-code/`, включая мак. Меньше движущихся частей в `settings.json`.
- **Прайс-таблица не нужна.** Claude Code сам считает деньги по каждой модели,
  включая модель советника и подагентов. `api_usd_equiv` берём как есть.

Чего в транскриптах нет вовсе — **процентов лимита подписки**. Их отдаёт
только statusline, и это единственное, ради чего пришлось трогать
`~/.claude/`.

### Реальный JSON statusline (версия 2.1.252)

Проверено на живой сессии, а не по документации:

```
session_id, transcript_path, cwd, prompt_id, session_name, version
effort.level                      model.id / model.display_name
workspace.current_dir / project_dir / repo.{host,owner,name}
cost.total_cost_usd / total_duration_ms / total_api_duration_ms
    / total_lines_added / total_lines_removed
context_window.total_input_tokens / used_percentage / context_window_size
    / current_usage.{input,output,cache_creation,cache_read}_tokens
exceeds_200k_tokens               fast_mode        thinking.enabled
prompt_cache.{warm,ttl,requests,misses,hit_ratio,cache_write_tokens,
              expected_rebuilds,recache_tokens_if_cold,expires_at}
rate_limits.five_hour.{used_percentage,resets_at}
rate_limits.seven_day.{used_percentage,resets_at}
```

`resets_at` — epoch в секундах. Отдельного ведра под Fable, как и предполагал
бриф, нет: долю Fable придётся оценивать косвенно.

**Времени в JSON нет.** Штампует statusline (`$EPOCHREALTIME`), иначе тик
получил бы время шиппера — на пять минут позже, и интервалы поехали бы.

## Что уже работает

### `scripts/claude-usage.py` — сканер транскриптов

Разбирает транскрипты в записи сессий и в лог тяжёлых результатов
инструментов. Дедуп по `message.id`: одно сообщение встречается в файле не раз
(резюме компакции, ретраи), без дедупа токены задваиваются.

```
python3 scripts/claude-usage.py status                       # сводка на экран
python3 scripts/claude-usage.py scan --out "…/Claude Usage/_data"
```

Первый прогон на 535 транскриптах из волта — полторы секунды.

Две находки на живых данных:

- **506 «сессий» с мака — пустышки.** `model: "<synthetic>"`, ноль токенов:
  OpenClaw запускает Claude Code, тот сразу отваливается. Отсеиваются, иначе
  любой счёт сессий утонул бы в них.
- Модель `claude-opus-5[1m]` — отдельный ключ: миллионное окно тарифицируется
  своей строкой. `advisorModel: claude-fable-5` объясняет, откуда в расходе
  Fable при работе на Opus.

### `scripts/claude-usage-ship.py` — тики и тулсет

Statusline дописывает сырой блоб в `~/.local/state/mara/ticks.raw` одним
`printf` — без `jq` и без сети, чтобы не тормозить строку состояния. Шиппер
разбирает накопленное, ужимает в строки тиков, снимает тулсет и везёт всё на
doctor.

Сырой файл забирается **переименованием**: statusline после этого откроет по
имени новый файл, и гонки за строку не будет. Один писатель на файл — сырьё
лежит в папке своего хоста.

Тулсет (§4 брифа) снимается из конфигов, а не хуком: `~/.claude.json`
(MCP по проектам), `~/.claude/settings.json` (плагины), `~/.claude/skills/`,
размер `CLAUDE.md`. Строка пишется, только когда меняется хэш.

### Правка в `~/.claude/statusline-command.sh`

Одна строка после `input=$(cat)`, бэкап рядом (`.bak-usage`):

```bash
printf '%s %s\n' "$EPOCHREALTIME" "$input" >> "${CLAUDE_USAGE_TICKS:-$HOME/.local/state/mara/ticks.raw}" 2>/dev/null || true
```

Работает: тики копятся. Ошибка записи строку состояния не роняет.

## Три вещи, из-за которых наивный счёт врёт

Всплыли на живых тиках, и они определили устройство агрегатора.

**Процент лимита целый.** И 5h, и 7d приходят целыми числами. Разность
соседних тиков почти всегда ноль, изредка единица. Поэтому считаем не по
тикам, а по шагам процента: интервал — это минуты работы между двумя
приращениями, а не секунды между двумя тиками.

**Значение приходит вразнобой.** Параллельные сессии отдают процент своей
свежести: на живых данных подряд идут 32, 32, 31, 32. Наивная разность дала бы
минус на ровном месте. Берём бегущий максимум внутри окна.

**Тиков очень много.** Statusline срабатывает после каждого ответа: пятеро
агентов дают десять тиков в минуту, 12 МБ в сутки в волт, который коммитится и
синкается. Серия одинаковых тиков одной сессии ужимается в одну строку с
`ts_last` и `n` — 201 тик стал 10 строками. Момент смены процента при этом
сохраняется точно: смена рвёт серию.

## Как считается атрибуция

Шаг процента раскладывается по сессиям пропорционально взвешенным токенам, и
доля пишется прямо в ход. Дальше любой срез — день, проект, модель, уровень
усилия, час — это просто сумма по ходам. Сумма долей внутри шага равна самому
шагу ровно, включая округление в файле.

Веса типов токенов — прайор из соотношения цен API (вход 1, выход 5, запись
кэша 1.25, чтение 0.1). Масштаб подбирается на чистых шагах — тех, где почти
все токены интервала принадлежат одной модели. Пока чистых шагов нет,
работает прайор, и это видно в недельном отчёте.

Доверие: `high` — в интервале одна сессия, `medium` — две, `low` — три и
больше либо интервал упирается в начало первого окна, где часть расхода
случилась до первого тика.

## Что где крутится

| Машина | Что | Когда |
|---|---|---|
| BetaPi | `claude-usage-ship.py` — разбор тиков, снимок тулсета, доставка | крон `*/5` |
| doctor | `claude-usage-agg.py` — пересборка всего и отчёты | крон `3-58/5` |

Агрегатор не хранит состояния: каждый прогон считает всё с нуля из сырья.
Транскрипты с мака приезжают только в конце сессии, и интервал недельной
давности может уточниться сегодня — инкрементальный кэш тут только мешал бы.
Полный прогон на 538 транскриптах — 2.5 секунды.

Файлы переписываются, только если содержимое изменилось, и все даты в шапке
взяты из данных, а не из часов. Иначе прогон раз в пять минут гонял бы
автокоммит и bisync круглые сутки.

## Приёмка §11

| Критерий | Состояние |
|---|---|
| Сумма оценок за интервал равна глобальному Δ% | **проверено** на живых интервалах, расхождений ноль |
| Параллельные сессии, правдоподобные оценки с флагами доверия | **проверено**: пять сессий разом, Dashboard их показывает |
| Отсутствие `rate_limits` не ломает коллектор и отчёты | **проверено** самопроверками обоих скриптов |
| В `Tools & MCP.md` видно подключённое, но не вызываемое | **проверено**: `basic-memory` в кандидатах на отключение |
| `rebuild` с нуля даёт те же отчёты | **проверено**: вторая сборка отдельным процессом с другим `PYTHONHASHSEED` не трогает ни файла |
| Ни одного вызова LLM в пайплайне | **проверено**: сети в скриптах нет вовсе, кроме `rsync` на doctor |
| Сброс недели не даёт отрицательных расходов, появляется недельный отчёт | логика проверена самопроверкой, **живого сброса ещё не было** (ближайший 3 сентября) |
| Отчёты открываются на телефоне через сутки работы | **ждёт суток**; фильтр R2 проверен: отчёты уезжают, `_data` нет |
| Калибровочные коэффициенты | **ждёт данных**: чистых шагов пока ноль |

## Отступления от брифа

- **Хуков нет.** Всё, что бриф просил собирать хуками, уже лежит в
  транскриптах. Если Claude Code перестанет писать что-то в транскрипт,
  вернуть хук — работа на полчаса.
- **SQLite-кэша нет** и, похоже, не понадобится: 538 транскриптов
  разбираются за две с половиной секунды. Заводить бинарник, который нельзя
  синкать и надо уметь пересобирать, ради такого объёма — лишняя деталь.
- **Сырьё не копируется в `_data`.** Транскрипты — уже append-only и уже в
  волте (`raw/claude-code/`), а это 175 МБ; вторая копия удвоила бы синк ни за
  чем. Сырой слой — это они и тики.
- **Вызовы инструментов не пишутся поштучно.** 538 сессий дали бы под миллион
  строк. Поимённо логируются только результаты тяжелее 20 КБ — из таких и
  состоит «куда ушёл контекст», — остальные учитываются суммой в записи
  сессии.
- **`project-map.json` не заведён.** Бриф просит свою карту «каталог →
  заметка проекта», но в волте уже есть канонический реестр сущностей, и
  отчёты линкуют проекты через него (`vault_common.canon_map`). Вторая карта
  тех же имён разъехалась бы с первой.
- **Регрессии весов по типам токенов нет.** Вместо неё одна ручка масштаба на
  модель. При целом проценте регрессия на четыре неизвестных ловила бы шум;
  когда чистых шагов накопится сотня, на тех же данных встанет МНК.

## Чего система не знает

- **Отдельного счётчика Fable в statusline нет.** Доля Fable — оценка по
  токенам, а не то число, что показывает `/usage`.
- **Мак невидим для тиков:** правки statusline там нет, и его расход попадёт в
  проценты только как чужой в общих интервалах. Токены и деньги мака при этом
  считаются: транскрипты приезжают. Чинится строкой в `install/client.sh`.
- **Первое окно неполное.** Проценты, которые мы застали при первом тике,
  кто-то уже съел; такой шаг помечен `window-baseline` и доверия ему нет.
- **`_data` стоит исключить из графа и поиска Obsidian** — вручную, в
  настройках («Files & Links → Excluded files»). Из синка он уже исключён.
