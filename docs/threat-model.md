# Модель угроз Мары

Карточка Т0.8 плана (`docs/PLAN-to-done.md`), ТЗ §15.2 и §18 Фаза 0 п.3.
Снимок кода на 2026-10-05, `main` @ `fafb970`. Номера строк — на этот
коммит; при расхождении верить коду, а не файлу.

Документ отвечает на три вопроса: где проходят границы доверия, кого мы
считаем злоумышленником и что отказом, и что из двенадцати сценариев §15.2
закрыто кодом, а что нет. Каждая дыра ведёт в карточку плана; дыры без
карточки собраны в Т0.9.

## 1. Границы доверия

```
телефон ──HTTP(S)+bearer──▶ contextd ──▶ реестр SQLite ──▶ волт (Markdown)
 (Store.kt)                 (contextd.py)  contextd.db       /srv/vault
                                 │                              │
              локальная сеть; с секретом — HMAC          ├─▶ R2 (rclone bisync, каждые 5 мин)
                                 ▼                              ├─▶ git-зеркало на том же диске
                    bigpc: прокси агента узла ─▶ Ollama, ASR    └─▶ шифрованный бандл на носители
                    (MARA_LLM_URL, MARA_ASR_URL)
                                                 облачные LLM ◀── queue-worker, daily-summary,
                                                 (OpenRouter)     пакет контекста для Hermes
                                                 Telegram    ◀── дайджесты звонков, утренняя сводка
```

| Граница | Кто по ту сторону | Чем держится |
|---|---|---|
| телефон → contextd | устройство с токеном | bearer, в базе только sha256 (`contextd.py:185–190`); 429 после 10 подряд 401 с адреса (`contextd.py:99–101`, `:609`); с TLS (Т0.9 п. 2) токен в локалке шифрован, у плагина и агента узла — пин сертификата до первого байта |
| сеть → contextd | любой в той же сети | слушает петлю, если не задан `MARA_BIND` (`contextd.py:1270`); без токена открыт только `/healthz` (`contextd.py:87`), `/metrics` — только с петли (`contextd.py:597`); с `MARA_TLS_*` рядом слушает TLS (`TLSСервер`), открытый порт сворачивается `MARA_PLAIN_BIND` |
| contextd → bigpc | вычислительный узел | без секрета — **ничем**, HTTP как есть; с `MARA_NODE_SECRET` — прокси агента узла: запрос и ответ подписаны HMAC-SHA256 общего секрета, аудио — только узлу, доказавшему секрет (`node_agent.к_узлу`, `node_agent.Прокси`, Т0.9 п. 5) |
| сеть → прокси агента на bigpc | любой в той же сети | до проверки подписи — только заголовки: тело не читается, соединений не больше восьми, тишина сокета — 60 с; пересылаются только `POST /transcribe` и `POST /api/generate`; Ollama за прокси слушает петлю, иначе её модель подменят мимо него (`docs/USER-MANUAL-STEPS.md`) |
| doctor → облачные LLM | провайдер модели | карточки `sensitive: true` не уходят (`queue-worker.py:54`, `daily-summary.py:62`); в пакет контекста — белый список полей (`context_pack.py:68`) |
| волт → R2 | Cloudflare и всё, что синкается с бакетом | фильтр `config/r2-filters.txt`: `raw/`, `.git/`, очередь, ключи плагинов не уезжают |
| волт/ядро → носители бэкапа | соседняя машина, внешний диск | gpg AES256 по парольной фразе (`core-backup.py:54`, `vault-backup.sh`) |
| модель → инструменты | ответ модели | аргументы `mara_correction` проверяются как недоверенные (`call_project.py:291`) |

## 2. Злоумышленник и отказ

**Злоумышленник** — тот, кто действует намеренно:

1. держит в руках телефон владельца (кража, утеря, чужие руки);
2. видит домашнюю сеть (гость, взломанное устройство в локалке);
3. пишет владельцу: присылает сообщение, письмо или говорит в звонке
   фразу, рассчитанную на модель (prompt injection);
4. контролирует пакет в цепочке поставки;
5. получил доступ к одному из облаков: R2, OpenRouter, Telegram, GitHub.

Публичный репозиторий — отдельный канал: всё, что в нём, знает каждый.
Поэтому в нём нет ни личных данных, ни адресов домашней сети.

**Отказ** — то же разрушение без умысла: падение диска, перезагрузка
посреди записи, кривой выкат, агент с лишними правами, массовая правка,
которой владелец не хотел. Мера против отказа — копия, проверка и точка
отката, а не авторизация.

## 3. Какие данные какую границу не пересекают

| Данные | Не уходят | Где держится |
|---|---|---|
| Сырое аудио звонков | никуда с doctor, кроме шифрованного бэкапа | ASR на bigpc получает его по сети (см. п. 9 разд. 4) |
| Сырые логи Telegram и Gmail | в волт, R2, бэкап | `blob_retention.py` чистит сырьё, манифест хранит `purged` |
| Сессии TDLib и токен Gmail | в git, R2, бэкап | `core-backup.py:39` `СЕКРЕТЫ=("tdlib","gmail")` |
| Тело карточки обязательства | облачные LLM | пакет контекста берёт пять полей фронтматтера (`context_pack.py:68`) |
| Карточки `sensitive: true` | облачные LLM | `queue-worker.py:54`, `daily-summary.py:62` |
| `raw/` волта | R2 | `config/r2-filters.txt` |
| Ключи плагинов Obsidian | R2 | `config/r2-filters.txt` |

**Что границу пересекает сознательно** — пусть будет записано:

- заголовок обязательства и `promised_to` уезжают провайдеру Hermes в
  пакете контекста. Карточка при этом помечена `cloud_allowed: false`:
  пометка относится к телу и цитатам, а не к пяти полям пакета;
- дайджест звонка и утренняя сводка уходят в Telegram — облако третьей
  стороны; с Т4.3 сводка называет и время звонка, за которым телефон не
  нашёл записи, и имя телефона (`pura70`). Номера и имени собеседника нет:
  причину телефон собирает из шаблонов без них, а сервер её ещё и
  санирует — номера в ней затираются (`contextd._причина`); имя так не
  поймать, его не пускает шаблон;
- волт уходит в R2 открытым текстом: в репозитории нет crypt-remote
  (`REMOTE=r2:mara-vault` в `scripts/vault-r2-sync.sh`). Шифрует ли
  конфиг rclone на doctor — не проверено. Это Т0.9 п. 4.

## 4. Двенадцать сценариев §15.2

Формат: **есть** — что держит сейчас, **дыра** — чего нет, **куда** —
карточка плана.

**1. Кража телефона.**
Есть: токен в EncryptedSharedPreferences (`android/.../Store.kt:20`); отзыв
одной командой `contextd.py --revoke dev_…`, после него устройство не
находится (`contextd.py:194–211`). В логах Android ни одного вызова `Log.*`.
Дыра: отзыв — ручной и с doctor; записей, которые лежат на телефоне до
выгрузки, ничто не защищает, кроме блокировки экрана самого телефона.
Куда: процедура отзыва — в ранбук ротации (разд. 5.2). Остальное
принимается как риск.

**2. Компрометация токена устройства.**
Есть: токен 256 бит (`token_urlsafe(32)`, `contextd.py:187`), в базе только
sha256, отзыв, `last_seen` у каждого устройства (`contextd.py:211`), 429
после десяти неверных попыток.
Дыра: срока жизни у токена нет; украденный и не замеченный токен работает
вечно. Сравнение по хешу в SQL — не постоянное по времени, но атакующий
подбирает прообраз sha256, а не сам токен, так что это не дыра.
С Т4.3 токен телефона пишет и здоровье захвата (`/v1/device/health`):
украденным можно завести ложные тревоги «записи нет» — строки в `alerts`
и `error` в утренней сводке — или погасить настоящие, назвавшись
`healthy`. Путь пускает только токен с `call` в allowlist (плагин Hermes
и узлы — 403), отзыв последнего токена телефона закрывает его тревоги.
С Т6.4 читать пакет обязательств и справку (`/v1/context/*`) токен со
списком может, только если в нём `memory:read` или `correction` (ADR-0009,
правка решения 4): украденный телефон со списком `call message …` открытых
обязательств не отдаёт. Телефон без списка (`null`) по-прежнему читает —
список ставится руками и явно: `--allow ID call message`.
Куда: Т0.9 п. 1 — показывать устройства и их `last_seen` в
`/metrics` уже можно, срок жизни — решение владельца.

**3. MITM и повтор загрузки.**
Есть: телефон отказывается слать по HTTP за пределы своей сети
(`android/.../Core.kt:465–496`); повтор безвреден — событие адресуется
содержимым через `dedupe_key` (`contextd.py:653`), второй раз оно не
создаётся.
Есть с 2026-10-15 (Т0.9 п. 2, сервер и клиенты на питоне): с сертификатом
(`MARA_TLS_CERT`, `MARA_TLS_KEY`) `contextd` слушает ещё и TLS на
`MARA_TLS_PORT` (8789). Сертификат самоподписанный (`contextd.py --tls-new`),
доверие — пин: отпечаток sha256 сертификата (`--tls-pin`). Цепочка до CA и
имя не годятся: адрес doctor — номер в локалке, имени для сертификата у
него нет. Плагин Мары (`MARA_CONTEXT_PIN`, версия 1.4.0) и агент узла
сверяют пин сразу после рукопожатия, до первого байта запроса: подставной
сервер не получает ни токена, ни тела. Пин при адресе `http://` — отказ без
похода в сеть; `https://` без пина — системное доверие, и самоподписанный
его не проходит. Рукопожатие — в потоке соединения с таймаутом: открывший
соединение и замолчавший не держит приём. Битый сертификат или половина
пары — `contextd` не стартует, а не остаётся молча на открытом порту.
Дыра: открытый порт 8788 по-прежнему слушает `MARA_BIND`, пока владелец не
закроет его для локалки (`MARA_PLAIN_BIND=127.0.0.1`), — а закрыть его
можно, только когда переедут все. Телефон пина пока не умеет и ходит по
8788 (дома) или через KeenDNS (`https://` с сертификатом роутера); участок
роутер → doctor у KeenDNS — открытый, если роутер не умеет HTTPS к
назначению. Кто ещё ходит открытым портом не с петли, видно в `/metrics`
(`mara_http_plain_remote_connections_total{from="lan"|"proxy"}`). Nonce и
подписи запроса нет — но повтор и так идемпотентен.
Куда: Т0.9 п. 2 — пин в приложении телефона (гейт Г2) и TLS на участке
doctor → прокси узла (п. 9); закрыть открытый порт — владелец
(`docs/USER-MANUAL-STEPS.md` §1.5).

**4. Вредоносный файл и неверный MIME.**
Есть: нюх содержимого по сигнатурам (`contextd.py:1000`), белый список
форматов, карантин неузнанного (`contextd.py:417`, `:951`); тело не больше
256 МиБ, JSON не больше 1 МиБ, сверху — 413 (`contextd.py:66`, `:70`).
Дыра: декодер ASR на bigpc получает файл, прошедший нюх, но не песочницу.
Куда: закрыто Т3.2; остаток — принятый риск.

**5. Prompt injection в сообщении, письме, транскрипте.**
Есть: сырой текст в пакет контекста не попадает — только пять полей
(`context_pack.py:68`, ТЗ §15); заголовок обрезан (`MAX_TITLE`) и
очищен; извлечение из звонков — локальная модель без инструментов.
Дыра: цепочка «чужая фраза в звонке → заголовок обязательства → пакет в
Hermes → модель с инструментом `mara_correction`». Инструмент умеет менять
статус обязательства, лимита частоты у него нет, подтверждения у
владельца — тоже. Худший исход — закрытые чужими словами обязательства;
след остаётся в журнале правок карточки.
Есть с 2026-10-10 (Т0.9 п. 3): текст заголовка и адресата в пакете — в
границах «…», шапка пакета называет его данными, а не инструкциями; из
текста вычищены знаки, которыми он мог бы подделать структуру пакета —
маркеры `<!-- -->`, код карточки `#…` (иначе чужая фраза подставила бы под
`mara_correction` id соседней карточки), сами границы, ссылки и разметка,
управляющие и невидимые символы (bidi, zero-width); срок и код едут только
по формату (`context_pack.данные`, `строка`).
С 2026-10-15 (Т6.3) та же очистка — и в ответе правки. Сам ответ
`mara_correction` тоже едет модели: заголовки, список «подходят несколько»,
список открытых на «не нашёл», конфликт версий (`current`,
`attempted_patch`). До этого они шли сырыми, а списки — без потолка. Теперь
в каждом не больше 15 заголовков и число остальных, `attempted_patch` —
только поля правки, заметка — до 500 знаков (`call_project._м`,
`СПИСОК_МАКС`, `ПОЛЯ_ПРАВКИ`, `ЗАМЕТКА_МАКС`); сырой ответ целиком плагин
модели больше не отдаёт. В реестр и тревогу конфликта идёт сырое, как было.
Есть с 2026-10-10 (Т3.1): не больше 20 принятых правок в час с одного
устройства (`contextd.ждать_с_правкой`, `MARA_CORRECTIONS_PER_HOUR`), дальше
`429` с `Retry-After`; окно — по строкам `events`, рестарт его не сбрасывает.
Куда: подтверждение владельца у закрывающих правок — М5.

**6. Агент с избыточными правами MCP.**
Есть: Basic Memory отдаёт 23 инструмента, из них 7 пишущих; у Claude Code
и Codex пишущие запрещены на клиенте (`scripts/mcp-readonly.py:31`,
ADR-0009). Hermes видит один пишущий инструмент — `mara_correction`.
Дыра: фильтр клиентский: сервер по-прежнему умеет писать в `/srv/vault`.
Новый клиент без фильтра получит запись.
Куда: ADR-0009 решил шлюз не строить и держать фильтр на клиенте; новый
клиент подключается только через `install/client.sh`, который фильтр
ставит. Принятый риск.

**7. Утечка через логи, бэкапы, виджеты.**
Есть: `log_line` пишет имена ключей, а не значения (`contextd.py:340`);
бэкапы шифруются (`core-backup.py:54`, `vault-backup.sh`); секреты
источников в бэкап не попадают (`core-backup.py:39`); перед облаком
работает `redact.py` (регулярки плюс Presidio). Виджетов в приложении нет.
Дыра: соседний бот на doctor пишет токен в journald (вне Мары, владельцу
сказано); волт в R2 открытым текстом (разд. 3).
Т9.1 (2026-10-11): хвост ошибки шага и причина DLQ обезличиваются
(`mi.обезличить`), токен бота с пробелом не попадает в адрес и трейсбек,
журнал TDLib — хеш вместо id собеседника (`tests/test_log_privacy.py`).
Остаток: имена карточек несут собеседника (переименование — Г4).
Куда: Т9.1 — gated sensitive mode; Т8.7 — виджеты, когда появятся;
Т0.9 п. 4 — R2.

**8. Повреждение и откат SQLite.**
Есть: WAL, `timeout=30`, автокоммит (`mara_ingest.connect`, `mara_ingest.py:195`); снимок
базы через backup API, после записи — расшифровка и `integrity_check`
(`core-backup.py:305`); перед выкатом шаг 2 ранбука ищет миграции.
Дыра: явных транзакций нет; `user_version` = 0, то есть версию схемы не
знает никто; учения восстановления полного состава не было.
Куда: Т2.1 (версия схемы), Т2.1б и Т2.1в (транзакции, проверки по
расписанию), Т3б.1 (учение). Порядок — `docs/migration-plan.md`.

**9. Сторонний вычислительный воркер.**
Есть (2026-10-14, Т7.2): сердцебиение узла — своим токеном; отчитаться за
bigpc (поставить его на паузу, объявить сервис лёгшим) без токена нельзя,
а токен узла ничего, кроме сердцебиения, не открывает. Без общего секрета
(ниже) bigpc по-прежнему отвечает на запросы к STT и Ollama без
авторизации: узел, занявший его адрес в сети, получит аудио и вернёт что
угодно — транскрипт и обязательства примутся как настоящие.
Есть с 2026-10-14 (Т0.9 п. 5): с общим секретом шаги doctor ходят не в
сервисы, а в прокси агента узла (`node_agent.Прокси`). Запрос подписан
HMAC-SHA256 (метод, путь, время, одноразовый номер, хеш тела); неподписанное,
просроченное или повторённое прокси не пересылает. Ответ подписан тем же
номером, с кодом и хешем тела, и без верной подписи не принимается. До
первого запроса doctor просит узел подписать свой номер (`/mara/hello`) —
аудио и текст уходят только узлу, доказавшему секрет (`node_agent.к_узлу`).
Дыра: включается секретом на обеих сторонах — пока его не завели, всё как
раньше. Подслушивание внутри сети подпись не снимает (TLS — Т0.9 п. 2), а
посредник, пересылающий привет живому bigpc, аудио получит, но ответ не
подменит. Доказательство узла doctor помнит минуту после последнего
проверенного ответа: если в эту минуту адрес займёт чужой, ему уйдёт один
кусок записи (около 25 секунд) — его ответ не сойдётся, и следующий
запрос снова начнётся с привета. Секрет один на все узлы, и имени узла в
подписи нет: когда вторым узлом станет GTR, он сможет ответить на привет
за bigpc — тогда секрет по узлу (ADR-0010 решение 5).
Куда: настройка — владелец (`docs/USER-MANUAL-STEPS.md`); TLS — Т0.9 п. 2.

**10. Зависимость из цепочки поставки.**
Есть: версии плагинов Gradle прибиты. С 2026-10-10 (Т0.9 п. 6): два venv
doctor описаны файлами с версиями и sha256 каждого колеса
(`install/requirements-venv.txt`, `-models.txt`, `-tdlib.txt`; ставятся с
`--require-hashes`), гейт держит границу «сторонних имён в `scripts/` ровно
два» (`tests/test_dependencies.py`), а job `osv` в CI гонит osv-scanner
(версия и контрольная сумма прибиты) по этим файлам и по `gradle.lockfile`,
который Gradle пишет там же из закрепления `releaseRuntimeClasspath` —
транзитивные зависимости приложения сканируются, хотя в репозитории не
закреплены; инструментарий сборки (AGP, lint, компилятор) не сканируется.
Дыра: лок-файл Gradle не коммитится (dl.google.com закрыт в облачной сессии
агента), так что две сборки в разное время могут разрешить разные
транзитивы; инструментарий AGP 8.5.2 тянет netty 4.1.93 и protobuf-java
3.22.3 с десятками записей OSV (первый прогон job `osv` в PR #140 со всеми
конфигурациями: 152 пакета, 43 записи) — это сборочная машина, не
приложение, и лечится подъёмом AGP (владелец, гейт Г2); job `osv` не обязательная проверка
защиты ветки — красный виден, но слить можно; живой venv на doctor с файлами
не сверялся (`pip freeze` против файла — владелец).
Куда: Т0.9 п. 6 — остаток владельца.

**11. Случайный публичный доступ к Control Plane.**
Есть: кода Control Plane нет. Аналог сегодня — сам contextd: по умолчанию
он слушает петлю, наружу открыт только `/healthz`.
Дыра: правило «Control Plane не слушает ничего, кроме петли и VPN, и без
входа не отвечает» ещё не записано как требование к волне 8.
Куда: Т8.1 — первым пунктом критерия закрытия.

**12. Опасная массовая правка или миграция.**
Есть: миграция ловится шагом 2 ранбука и гейтом Г4; `_ужать_ledger`
перестраивает таблицы под `begin immediate` (`mara_ingest.py:154`);
синк в R2 не удалит больше 25 файлов за раз (`--max-delete 25`).
Дыра: массовую правку волта мимо пути правок ничто не видит — так 21.09 и
28.09 закрылись 192 обязательства, в базе следа нет. Правки через
`mara_correction` с 2026-10-10 ограничены 20 в час с устройства (п. 5), но
массовую правку мимо этого пути лимит не видит.
Куда: Т2.0 (перенос состояния), `docs/migration-plan.md`.

### 5.2. Ранбук ротации

| Секрет | Как сменить | Что проверить |
|---|---|---|
| Токен устройства | `contextd.py --revoke dev_…`, затем `--pair "<имя>"` и новый токен в приложение | старый токен получает 401 |
| Токен узла | `contextd.py --revoke dev_…`, затем `--pair-node <узел>` и новый токен в окружение агента | `node_agent.py --once` со старым — «токен не принят», с новым — «сердцебиение: 200» |
| Ключ TLS contextd | убрать `contextd.crt` и `contextd.key`, `contextd.py --tls-new` в тот же каталог, `systemctl restart contextd`; новый пин (`--tls-pin`) — в `MARA_CONTEXT_PIN` плагина и агента узла | клиент со старым пином — «сертификат не совпал с пином», запрос не ушёл; с новым — ответ |
| Токен бота | новый в @BotFather, правка `/etc/mara/contextd.env`, `systemctl restart contextd` | следующий дайджест дошёл |
| `OPENROUTER_API_KEY` | новый ключ у провайдера, правка `~/.config/mara/env` | следующий прогон queue-worker без 401 |
| OAuth Gmail | `gmail_ingest.py --login --port …` | `gmail` в `/metrics` снова растёт и сбрасывается |
| Сессия TDLib | повторный вход tdlib-ingest | `tdlib` в `/metrics` свежий |
| Парольная фраза | новая фраза, прогон `core-backup.py` и `vault-backup.sh`; старые копии расшифровываются старой — её в менеджере паролей не удалять, пока копии живы | учение восстановления на новой копии |
| Ключи R2 | новый токен в Cloudflare, правка конфига rclone | один прогон `vault-r2-sync.sh` без ошибки |

Ключ правится в файле редактором, а не через переменную шелла или
командную строку: иначе он попадёт в историю и журнал.
