# RUNBOOK — восстановление из копии: журнал учений

Процедура — раздел «Восстановление» в `docs/backup-core.md` (девять шагов
ТЗ §5.3, bash-блок разбирает `tests/test_restore_drill.py`). Здесь не вторая
копия процедуры, а запись каждого учения: что делали, сколько заняло, что
проверили и чего учение не покрывает. Числа — только из строк лога учения
(`drill.log`, строки `=== […] rc=…, шаг N с, от начала M с` и `итого`) и
из вывода самих команд.

**Чего учение не покрывает — честно.**

- Шаги 1 и 9 не выполнялись: писатели не останавливались, сервис не
  возвращался, crontab не снимался и не ставился. На doctor остановка и
  запуск `contextd` — те же шаги 3 и 6 `docs/RUNBOOK-deploy.md`
  (тринадцать прогонов), снятие и возврат crontab живьём не гонялись.
- Состав — текущий (§5.3 не полностью): секреты и конфигурация в копию не
  входят (Т3б.5 п.5: `~/.hermes/.env`, парольная фраза, crontab,
  TLS-ключи) — восстановленная система без них не запустится; копия вне
  doctor (п.8) отсутствует, источником был локальный диск той же машины.
  Чекбокс §17.3 п.5 — «по текущему составу»; повторить тем же скриптом
  после Т3б.5 п.5/п.8, лучше на другой машине.
- Сверка приёма (шаг 8) проверяет файлы блобов по абсолютным путям реестра
  (`contextd_reconcile.py`, `os.path.exists(r["path"])`): на doctor это
  живые файлы, а не копия. На чистой машине с тем же путём корня проверка
  была бы по копии; про копию здесь говорит `restore_check` (шаги 5–8).
- `raw/` (транскрипты агентов) в бандл не входят по замыслу (Т3б.7): в
  восстановленном волте их нет.
- RTO не измерен: восстановление — 458 с, из них 380 с — расшифровка
  488 аудио по файлу (ускорять нечем, пока не понадобится); запуск
  сервиса на восстановленном не делался.

**Урок для ранбука.** Шаг 2 (`--drill-only`) идёт до восстановления и
только против корня, который записан в реестре: с другим `MARA_BLOBS`

менять в нём нечего; скрипт учения подменял, и это его ошибка.

### Скрипт учения 1 (как запускался; шаг 2 — с поправкой корня)

```bash
#!/bin/bash
# Учение Т3б.1: шаги 2–8 docs/backup-core.md «Восстановление» в чистый каталог.
# Живые /srv/mara-blobs, /srv/vault, кроны и демоны не трогаются.
set -uo pipefail
REPO=~/mara-second-brain; cd "$REPO" || exit 2
SRC=/mnt/backup/mara; PASS=~/.config/mara/backup-pass
D=/var/tmp/drill-$(date +%Y%m%d-%H%M%S); R=$D/blobs; V=$D/vault
mkdir -p -m 700 "$D"; exec > >(tee "$D/drill.log") 2>&1
export VAULT=$V MARA_VAULT=$V MARA_CORE_TARGETS=$SRC MARA_STATE=$D/state  # отметки и курсор — не в живой state
install -d -m 700 "$D/state"
T0=$(date +%s); L=$T0
шаг() { local n=$(date +%s); echo "=== [$1] rc=$2, шаг $((n-L)) с, от начала $((n-T0)) с"; L=$n; }
echo "учение: $D, код $(git rev-parse --short HEAD), $(date -Is)"
# Шаг 2 — против корня из реестра (живого), до восстановления; с корнем учения — красный.
scripts/core-backup.py --drill-only --targets "$SRC"; шаг "2 манифест и хеши" $?
export MARA_BLOBS=$R
CORE=$(ls -1 "$SRC"/core-*.tar.gz.gpg | tail -1); BUNDLE=$(ls -1 "$SRC"/vault-*.bundle.gpg | tail -1)
echo "копия: $(basename "$CORE"), бандл: $(basename "$BUNDLE")"
gpg --batch --pinentry-mode loopback --passphrase-file "$PASS" -o "$D/core.tar.gz" -d "$CORE"; шаг "3 расшифровка ядра" $?
install -d -m 700 "$R" && tar -xzf "$D/core.tar.gz" -C "$R"; шаг "3 распаковка" $?
scripts/core-backup.py --verify "$R"; шаг "3 verify" $?
rm -f "$R/manifest.json" "$D/core.tar.gz"
( set -eo pipefail; cd "$SRC"; [ -d calls ] || exit 0
  find calls -name '*.gpg' | while read -r f; do
    out="$R/${f%.gpg}"; mkdir -p "$(dirname "$out")"
    gpg --batch --quiet --pinentry-mode loopback --passphrase-file "$PASS" -o "$out" -d "$f"
  done ); rc=$?; шаг "3 аудио ($(find "$R/calls" -type f 2>/dev/null | wc -l) файлов)" $rc
gpg --batch --pinentry-mode loopback --passphrase-file "$PASS" -o "$D/vault.bundle" -d "$BUNDLE" && git bundle verify "$D/vault.bundle"; шаг "3 бандл волта" $?
git clone -q "$D/vault.bundle" "$V"; rc=$?; шаг "3 клон волта ($(find "$V" -name '*.md' -not -path '*/.git/*' | wc -l) md)" $rc
rm -f "$D/vault.bundle"
python3 scripts/mara_ingest.py --migrate; шаг "4 migrate" $?
python3 scripts/vault_manifest.py --check --vault "$V"; шаг "3а манифест до переноса" $?
python3 scripts/ledger_import.py --dry-run --vault "$V"; шаг "4а перенос проба" $?
python3 scripts/ledger_import.py --vault "$V"; шаг "4а перенос" $?
python3 scripts/restore_check.py --root "$R" --vault "$V"; шаг "5-8 restore_check" $?
python3 scripts/vault_rebuild.py --check --diff --vault "$V" | tail -20; шаг "6 rebuild --check" ${PIPESTATUS[0]}
python3 scripts/vault_rebuild.py --into "$D/vault-rebuilt" --vault "$V"; шаг "6 rebuild --into" $?
python3 scripts/vault_manifest.py --check --vault "$V"; шаг "4а манифест после переноса" $?
python3 scripts/contextd_reconcile.py --root "$R" --vault "$V" --daemon-url ""; шаг "8 сверка приёма" $?
echo "итого: $(( $(date +%s) - T0 )) с; размер: $(du -sh "$D" | cut -f1); лог: $D/drill.log"
```
