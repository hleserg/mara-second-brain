## 0. Что строим одной фразой

Один markdown-волт, который одновременно: (а) читается человеком в Obsidian с телефона и десктопа, (б) служит долговременной памятью ассистенту Маре, (в) даёт Claude Code и Codex контекст и историю проектов, (г) пополняется автоматически из всех источников без ручной работы.

## 1. Принципы (нарушать нельзя)

1. **Файлы — source of truth.** Любой индекс, БД, граф, эмбеддинги — производные и восстановимы из markdown. Если завтра сдохнут все сервисы, база остаётся читаемой папкой с текстом.
2. **Graceful degradation, а не отказ.** Запись сырья работает всегда и локально. Обогащение (дистилляция, автосвязи) — опционально и догоняемо. Никогда не делать запись зависимой от облака.
3. **Local-first.** Ничего критичного не должно зависеть от политики стороннего провайдера. Облако — только для «поумнеть», не для «жить».
4. **Один агент — один файл.** Два процесса не пишут в один файл одновременно. Это главное правило против мердж-боли.
5. **Идемпотентность.** Повторный прогон ingest не создаёт дублей. Ключ — `session_id`/хеш источника.
6. **Приватность по умолчанию.** Всё, что помечено `sensitive: true`, не уезжает в облачные API ни при каких условиях.

## 4. Схема фронтматтера

Единый канон для всех заметок. Ingest-скрипты обязаны его соблюдать.

```yaml
---
title: "Мигрировали Мару на DeepSeek V4 Pro 0423"
type: session              # session|decision|howto|note|person|project|tool|place|concept|daily|event
source: claude-code        # claude-code|codex|claude-chat|hermes|git|calendar|mail|browser|geo|manual
source_id: a1b2c3d4        # session_id / хеш источника — ключ идемпотентности
created: 2026-08-30T14:02:00+03:00    # когда файл написан
occurred: 2026-08-30                   # когда событие РЕАЛЬНО произошло
learned: 2026-08-30                    # когда Сергей это узнал/понял (опционально)
project: "[[mara]]"
tags: [infra, llm, openrouter]
sensitive: false           # true → только локальная дистилляция, в облако не уходит
distilled: true            # false = сырьё ждёт обработки в очереди
relations:
  - uses: "[[deepseek-v4-pro]]"
  - part_of: "[[project-mara]]"
---
```

**Три разные даты — принципиально.** `created` ≠ `occurred` ≠ `learned`. Это то, что делает возможными запросы «что я делал вчера», «когда я узнал про X», «когда познакомился с Y». Скрипты обязаны заполнять `occurred` реальной датой события, а не датой записи файла.

## 5. Автосвязи без галлюцинаций

**Проблема:** LLM охотно проставляет `[[wikilinks]]` на несуществующие сущности → битые ссылки и разрастание графа в кашу.

**Решение — реестр сущностей:**

1. `entities/` — единственный источник канонических имён. Каждая сущность = один файл с `aliases:` во фронтматтере.
2. `_system/entity-index.json` — плоский список `{canonical, aliases[], type}`, перегенерируется при каждом изменении `entities/`.
3. **Перед любой дистилляцией** промпт получает этот индекс. Правило для модели: *«Проставляй `[[wikilink]] `только на сущности из переданного списка. Если встретил новую значимую сущность — не линкуй её, а перечисли в поле `new_entities` ответа.»*
4. Скрипт создаёт карточки из `new_entities` (тип + первое упоминание + дата), затем **второй проход** проставляет ссылки. Два прохода, не один.
5. **Entity resolution:** «Сергей / Sergey / hleserg» — одна карточка с алиасами. Дедуп по нормализованному имени + косинусная близость эмбеддингов > 0.85 → в очередь на подтверждение, не сливать автоматически.
6. Еженедельный скрипт-линтер: находит `[[X]]` без файла `X` → пишет отчёт в `_system/broken-links.md`.

## 7. Мара: политика захвата

**Ключевое: дневник — это ОДИН ИЗ потоков, а не всё.** Мара фиксирует всё значимое, что проходит через диалог с ней. Ниже — полная политика. Вставить в `AGENTS.md` / оперативную спеку Мары.

### 7.1. Что фиксировать (все категории)

| Категория | Признак | Куда |
|---|---|---|
| **Технические решения** | выбрали X вместо Y, и вот почему | `kb/decisions/` |
| **Факты и знания** | как что работает, что выяснили, что сломалось и как чинили | `kb/howto/`, `kb/notes/` |
| **Состояние проектов** | что сделано, что следующее, что застряло | `entities/projects/<name>.md`, секция статуса |
| **Люди, места, инструменты** | появилась новая сущность | `entities/` + карточка |
| **События с датой** | когда что произошло, когда узнал, когда познакомился | `timeline/` |
| **Дневник** | как прошёл день, новости, успехи, проблемы, настроение | `daily/YYYY-MM-DD.md` |
| **Договорённости и обещания** | «надо сделать до пятницы», «напомни» | `kb/notes/` + задача |

**Правило по умолчанию: если сомневаешься — фиксируй.** Лишняя заметка стоит дёшево, потерянный контекст — дорого. Уплотнение мусора — забота еженедельного defrag, а не момента записи.

### 7.2. Блок дневника — вставить как есть

```markdown
## Дневник: что фиксировать молча

Триггер: Сергей рассказывает о себе, а не ставит задачу и не задаёт вопрос.

Фиксируем:
- как прошёл день, что делал, где был
- новости и его реакция на них
- успехи, чем доволен, чем хвастается
- проблемы, раздражение, усталость, то что наболело
- новые люди, места, знакомства
- что понял, что решил, что передумал

Куда: append в daily/YYYY-MM-DD.md, секция с таймстампом.
Людей и места — карточкой в entities/, связь проставить.

Как писать:
- его словами, а не канцеляритом. "заебался с MAX98357A" остаётся
  "заебался с MAX98357A", а не "испытывал затруднения при работе с усилителем"
- эмоция — такой же факт, как дата. Не сглаживать
- если про эмоции, проблемы или третьих лиц — ставить sensitive: true.
  Такое дистиллируется только локально, в облако не уезжает

Чего не делать:
- не спрашивать "хочешь, я это сохраню?" — просто сохранять
- не отчитываться "записал!"
- не дописывать от себя выводы о его состоянии
```

### 7.4. Технически: как Мара пишет

Три пути, по убыванию предпочтения:

1. **Плагин Basic Memory для Hermes** — инструменты `bm_write`, `bm_edit` (append/prepend/replace-section), `bm_search`, `bm_read`, `bm_context`, `bm_recent`. Автозахват: аппендит обмены в session-транскрипт, на конце сессии пишет summary.
   ⚠️ **Штатная установка сломана:** плагин ставит `manifest_version: 2`, а инсталлер `hermes plugins install` поддерживает только v1 → падает. Фикс в PR upstream, но не в релизе.
   **Обход:** `git clone https://github.com/basicmachines-co/basic-memory.git` + `ln -snf "$PWD/basic-memory/integrations/hermes" ~/.hermes/plugins/basic-memory`. Runtime грузит v2 нормально, ломается только инсталлер.
   ⚠️ Слэш-команды `/bm-*` не появляются в gateway-сессиях (баг discovery) — использовать `bm_*` инструменты напрямую.
2. **MCP:** Basic Memory как MCP-сервер в `~/.hermes/config.yaml`, инструменты префиксуются `mcp_basicmemory_*`.
   ⚠️ **MCP недоступен в cron-сессиях.**
3. **Файловые тулзы** `write_file`/`patch` с абсолютным `--workdir` — самый тупой и надёжный fallback.

⚠️ **Cron не пишет в persistent memory** (cron-сессии идут с урезанным контекстом, memory-провайдер не инжектится). Все регулярные задачи (дневная сводка, defrag, линтер) делать через **script-only cron `--no-agent --script`** — детерминированный shell без LLM. Это обходит баг и не жжёт токены.

⚠️ **Cron-тикер молча умирает** (background-тред внутри gateway, `hermes cron status` врёт про живость). Нужен **внешний watchdog**: systemd-таймер на Mac mini, который проверяет реальный факт выполнения последней задачи (по таймстампу файла-маркера) и рестартит gateway при простое > 2 циклов. Плюс `systemd_watchdog_seconds: 120` в конфиге.

⚠️ Memory-flush при рестарте gateway может перезатереть `MEMORY.md`. **Критичное знание держать в файлах волта, а не в `MEMORY.md`.** `MEMORY.md` — тонкий кэш, не хранилище.

## 8. Дистилляция и эмбеддинги

### 8.1. Дистилляция — облако

- **Модель по умолчанию: DeepSeek V4-Flash через OpenRouter** (~$0.14/$0.28 за 1M вход/выход). Прикидка: ~50 сессий + 30 чатов + 30 дневных сводок в месяц ≈ **$0.20/мес**.
- **Fallback на качество: Claude Haiku 4.5** ($1/$5, batch −50%) — тот же объём ≈ $1.66/мес. Переключатель в конфиге, не хардкод.
- **Обязательно включить prompt caching** на системном промпте дистиллятора (он большой — там реестр сущностей). У DeepSeek cache-hit почти бесплатный.
- Промпт дистиллятора хранить в `_system/prompts/` в git — он будет эволюционировать, нужна история.

### 8.2. Эмбеддинги — локально, всегда

- **Модель: `bge-m3` или `qwen3-embedding` через Ollama** (не `nomic-embed-text` — у него слабее кириллица; не `mxbai-embed-large` — контекст всего 512 токенов, режет длинные заметки).
- Инкрементальный индекс — на `doctor` (CPU достаточно).
- **Первичный bootstrap всей истории — на GTR** через SSH: разбудил, прогнал батч, забрал результат. Не грузить Mac mini (там 8 ГБ и Hermes).
- Стоимость: $0. Время: минуты.

### 8.3. PII-редакция — обязательный слой

Перед **любым** облачным вызовом:
1. Регэкспы на секреты: `sk-`, `ghp_`, `-----BEGIN * PRIVATE KEY`, `Bearer `, строки вида токенов/паролей.
2. Microsoft Presidio (`presidio-analyzer` + `presidio-anonymizer`) с кастомными recognizer'ами.
3. `sensitive: true` → **облако не трогает вообще**, только локальная модель или вообще без дистилляции (сырьё остаётся как есть).
4. Гео — огрублять до города.

Presidio сам предупреждает, что ловит не всё. Для реально критичного — не отправлять, а не «отредактировать и отправить».

### 8.4. Graceful degradation — три слоя

1. Облако живо → полная дистилляция + автосвязи.
2. Облако недоступно → сырьё пишется в `raw/` с `distilled: false`, задача уходит в `_system/queue/`, догоняется при восстановлении. Поиск по базе (ripgrep + локальные эмбеддинги) работает.
3. Всё сдохло → плоский markdown в git, читаемый глазами и Obsidian.

**Тест обязателен:** отключить сеть, прогнать сессию Claude Code, убедиться что сырьё записалось и задача в очереди.

---

## 9. Временной слой

- `daily/YYYY-MM-DD.md` собирается ночным script-only cron: git-коммиты + сессии + календарь + гео + записи Мары за день.
- Запросы — через **Obsidian Bases** (`.base`-файлы, читают фронтматтер, быстрее Dataview). Готовые вьюхи:
  - «Что я делал вчера / за неделю» — фильтр по `occurred`
  - «Когда я узнал про X» — фильтр по `learned` + связь на `[[X]]`
  - «Когда познакомился с Y» — `timeline/` + `type: event`
  - «Статус проекта Z» — все заметки со связью на `[[Z]]`, сортировка по `occurred`
- **Bases читает только frontmatter-properties**, не inline `key:: value`. Все метаданные — во фронтматтер.
- Dataview оставить для сложной логики, которую Bases не тянет.

## 10. Гигиена базы

- **Еженедельный defrag** (script-only cron): дедуп по `source_id` и по близости эмбеддингов, уплотнение однотипных заметок, перенос старше 6 месяцев в `archive/`.
- **Линтер битых ссылок** → `_system/broken-links.md`.
- **Правило дистилляции:** в `kb/` попадают только факты, решения, выводы. Транскрипты живут в `raw/` и в `kb/` не копируются. Если `kb/` начнёт напоминать свалку логов — дистиллятор сломан, чинить промпт.
- Бэкапы 3-2-1: `doctor` + bare-зеркало + периодический зашифрованный `git bundle` на внешний носитель. **Раз в квартал — тест восстановления** (склонировать бандл, переиндексировать Basic Memory из markdown, проверить что поиск работает).

## 11. Безопасность

- Все MCP-серверы — **только на loopback**, никогда `0.0.0.0`. Наружу не выставлять.
- Версии MCP-серверов пинить, changelog читать перед обновлением. Экосистема дырявая (значительная доля публичных серверов без аутентификации и с SSRF).
- Не давать агенту-читателю `raw/untrusted/` деструктивные инструменты в том же контексте.
- Секреты — не в волте. Никогда. Если попали — вычистить из истории git, не просто удалить файл.
- Отдельный профиль Hermes для Вани: изолированные config/session/memory, урезанный toolset (без terminal, file-write, browser), свой системный промпт. **Не смешивать с профилем Мары.**

## 13. Чего НЕ делать

2. **Не синкать `.git/`, `.smart-env/`, `.basic-memory/` через R2.**

5. **Не грузить Mac mini** локальными эмбеддингами и LLM — там 8 ГБ и Hermes.
6. **Не завязываться на `beta-pi`.**
7. **Не отправлять `sensitive: true` в облако** ни при каких условиях, включая «просто на пробу».
8. **Не давать двум процессам писать в один файл.**
9. **Не хранить критичное знание в `MEMORY.md`** — его может перезатереть flush.
10. **Не копировать транскрипты в `kb/`.**

## 14. Тест поведения Мары (регрессия, раз в месяц)

Правило «не давать непрошеных советов» — самое трудноудерживаемое. Любая модель дрейфует обратно в режим полезного помощника через 3–4 реплики, особенно если в жалобе есть техническая составляющая — модель распознаёт задачу и кидается решать.

**Сценарий:** скинуть Маре описание проблемы с технической составляющей, без вопроса. Продолжить нытьём ещё 4–5 реплик.
**Провал:** появилось «а ты пробовал», «может, стоит», «зато», «я слышу тебя», уточняющий допрос, бодрость.
**Действие при провале:** усилить формулировку в SOUL.md конкретным примером сорвавшейся реплики. Негативные правила работают только с примерами.

**Второй тест:** проверить, что при этом Мара **всё равно записала** проблему в `daily/` с `sensitive: true`. Молчаливость в диалоге не должна ломать захват.
