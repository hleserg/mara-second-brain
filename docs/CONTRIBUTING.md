# Правила разработки и управления агентами

Нормативный источник — `docs/TZ-master.md` §14 и §22. Здесь — рабочая
выжимка, которую читают перед каждым этапом.

## Роли

- Claude Code — основной исполнитель: анализ, код, тесты, документация, PR.
- Codex — независимый ревьюер diff, инвариантов, миграций, безопасности.
  Не подтверждает выводы Claude, а проверяет их. Путь запуска: `codex exec`
  через skill `codex-advisor` (CLI 0.152.1 стоит на BetaPi, **нужен логин
  владельца**: `codex login`).
- Владелец — финальная инстанция: архитектурные решения, опасные миграции,
  изменения приватности, выкат на doctor, полевые проверки.
  **Merge в эту инстанцию больше не входит**: поправка владельца — «мердж по
  готовности сам». Claude Code мержит сам, когда выполнены все условия
  §14.2а (зелёный CI, зелёный гейт на смерженном дереве, пройденное ревью,
  не больше пяти кругов) — и никогда на красном гейте, при неразрешённом
  конфликте или ломая живого потребителя `main`.

## PR-only

- В `main` напрямую не коммитим. Ветка на каждую логическую порцию:
  `phase<N>/<тема>` для этапов ТЗ, `fix/<тема>` для правок по ревью,
  `docs/<тема>` для документов; PR в `main`.
- До merge — зелёный `bash scripts/run-tests.sh` (на BetaPi) и gradle-тесты на
  doctor, если трогали `android/`. Результаты прогона — в описании PR числами.
- Гейт делает себе песочницу под `$TMPDIR` и сносит её на выходе; то же делает
  `tests/__init__.py` при прямом `python3 -m unittest tests.test_X`. Всё, что
  тест записал во временный каталог, после прогона исчезает. Нужны артефакты
  упавшего теста — `MARA_KEEP_TMP=1`, путь к песочнице будет напечатан.
- PR с миграцией схемы, изменением модели данных, безопасности или рекордера
  получает независимый review Codex до merge. Codex недоступен — ревьюером
  становится субагент (поправка владельца 2026-09-03 к §14); чей бы ни был
  круг, **больше пяти кругов не ведём**: пятый без схождения — стоп и вопрос
  владельцу, а не шестой круг.
- Секреты, сгенерированные артефакты (APK, индексы, дампы) не коммитятся.
- Аварийная правка тоже идёт PR-ом; review — после.
- Ветка `ambient-memory-core` полностью влита в `main`, оставлена только как
  история; новую работу от неё не ведём.

Branch protection на `main` **включена 2026-09-11**: обязательные проверки
`python` и `kotlin`, force-push и удаление ветки запрещены, `enforce_admins`
выключен — чтобы ff-мердж по готовности остался рабочим. До этого она была
недоступна (приватный репозиторий на плане Free, 403 и на protection, и на
rulesets); репозиторий публичный с 2026-09-03, и защита стала возможной.

Имена работ в `.github/workflows/tests.yml` — `python` и `kotlin` — это и есть
контексты обязательных проверок. Переименовать работу через `name:` значит
переименовать контекст: защита начнёт ждать того, чего никто не присылает, и
каждый PR встанет в `BLOCKED` с двумя зелёными галочками. Русские названия
живут комментарием рядом с id работы.

`Require review from Code Owners` включать по-прежнему **нельзя**: причина в
`.github/CODEOWNERS` — свой PR не одобришь, и мердж встанет до админского
байпаса.

## Описание PR

По §19 ТЗ: цель и пункты ТЗ; что было в baseline; решение и альтернативы;
изменения схемы/API; миграция и откат; влияние на приватность и безопасность;
ресурсы Doctor/Big PC/GTR/телефона; тесты с фактическими результатами; нужен
ли полевой тест и проведён ли; наблюдаемость и поведение при отказе;
документация; известные ограничения; чек-лист ревью Codex.

## Ограничения агентов (guardrails этапа)

Фиксируются до запуска fan-out и действуют по умолчанию:

| Параметр | Значение |
|---|---|
| Субагентов одновременно | не больше 3 |
| Рекурсивный swarm | запрещён без разрешения владельца |
| Scope субагента | ограничен списком файлов, deliverable и условием остановки |
| Одинаковое исследование несколькими агентами | не дублировать |
| Перед новым fan-out | суммировать уже полученное |
| Бюджет этапа | не больше 2 часов wall time и ~2 M токенов на этап; при 80 % — стоп новых исследований, сохранить промежуточное, эскалировать |
| Инструменты субагентов аудита | только чтение (Explore) |
| Write scope | только файлы своей ветки; `main`, волт `/srv/vault`, секреты в `/etc/mara`, `~/.hermes/.env` — не трогать |
| Точки одобрения владельцем | любая destructive-миграция; изменение приватности; правки на телефоне; выкат на doctor. Merge — **не** точка одобрения |
| Обход лимита цепочкой новых сессий | запрещён |

## Маршрут работ

Порядок задач и гейты — `docs/PLAN-to-done.md`. Оттуда берётся следующая
незакрытая карточка; порядок не придумывается заново каждой сессией. PR,
закрывающий пункт плана, ставит галочку в том же PR и обновляет таблицу §7 в
`docs/current-state-audit.md` (§22.14 ТЗ).

## Что не заявляем без доказательства

Пункт меню стороннего приложения, гипотеза или неподтверждённая возможность —
не интеграция. «Отчёт на удалённый сервер» в ACR Phone не называем webhook до
`RES-REC-001` (ТЗ §7.3, §20).
