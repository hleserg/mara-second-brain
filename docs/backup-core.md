# Бэкап ядра: база, метаданные, аудио

Волт с сентября 2025 возит `vault-backup.sh`, а ядро приёма не возил никто.
`contextd.db` и дерево `/srv/mara-blobs` не попадали ни в одну копию: ни в
git-зеркало, ни в бандл, ни в R2. Диск doctor умирает — исчезают события,
работы, дайджесты и все записи разговоров, и узнаём мы об этом в тот
единственный день, когда они понадобились. Это P0-2 из
[аудита](current-state-audit.md) и ТЗ §5.3.

Возит `scripts/core-backup.py`. Установка в крон — отдельный PR (P0-5),
здесь только сам инструмент и порядок восстановления.

## Что уезжает

| Что | Как | Почему так |
|---|---|---|
| `contextd.db` | снимок через SQLite backup API | под живым демоном WAL живёт отдельным файлом, `cp` даёт обрубок |
| `manifests/`, `transcripts/`, `extractions/` | вместе с базой в один `tar.gz`, GPG AES256, ротация по счёту | мелочь, дешевле возить целиком |
| `calls/` (аудио) | пофайловое зеркало `<хеш>.<ext>.gpg` на носителе | имя файла — хеш содержимого, значит «уже лежит» = «то же самое»; инкрементальность бесплатно |

Список внутри архива — allowlist, а не исключения: новый каталог в
`/srv/mara-blobs` по умолчанию **не** уезжает. Так безопаснее ошибиться.

## Что не уезжает

`tdlib/` и `gmail/` — состояние сессии Telegram и refresh token Gmail. ТЗ
§11: credentials и session-файлы denylisted из Git, R2 и бэкапов. Возить
ключи по сетевым шарам ради экономии двух логинов не стоит того.

**Следствие для восстановления:** после разворачивания нужен повторный вход
в Telegram (код на телефон) и повторный OAuth Gmail. Данные при этом целы —
пересинхронизируется только позиция чтения.

Парольная фраза (`~/.config/mara/backup-pass`, режим 600) лежит только на
doctor. Умрёт doctor — архивы без неё макулатура, поэтому копия фразы в
менеджере паролей у владельца обязательна. Это та же фраза, что у волта.

## Запуск

```bash
scripts/core-backup.py                      # бэкап + проверка восстановления
scripts/core-backup.py --drill-only         # только развернуть свежий архив
scripts/core-backup.py --self-check         # круг на игрушечном корне
```

Носители те же, что у волта: `/mnt/backup/mara` и `/mnt/win-backups/mara`.
Второй может быть отключён — это не повод валить прогон; ни одного
записанного носителя — повод.

Каждый удачный прогон **сам** разворачивает то, что только что записал:
расшифровка с носителя, `pragma integrity_check`, сверка счётчиков таблиц с
манифестом, сверка хешей метаданных и расшифровка до трёх записей из
зеркала аудио. Бэкап, который ни разу не разворачивали, — не бэкап, а
надежда.

## Восстановление

```bash
# 0. Парольная фраза из менеджера паролей
install -m 600 /dev/stdin ~/.config/mara/backup-pass   # вставить фразу, Ctrl-D

# 1. Убедиться, что архив читается, прежде чем что-то трогать
scripts/core-backup.py --drill-only --targets /mnt/backup/mara

# 2. Развернуть базу и метаданные
cd /mnt/backup/mara
gpg --batch --pinentry-mode loopback --passphrase-file ~/.config/mara/backup-pass \
    -o /var/tmp/core.tar.gz -d "$(ls -1 core-*.tar.gz.gpg | tail -1)"
mkdir -p -m 700 /srv/mara-blobs && tar -xzf /var/tmp/core.tar.gz -C /srv/mara-blobs
rm /srv/mara-blobs/manifest.json /var/tmp/core.tar.gz

# 3. Аудио из зеркала
cd /mnt/backup/mara && find calls -name '*.gpg' | while read -r f; do
  out="/srv/mara-blobs/${f%.gpg}"; mkdir -p "$(dirname "$out")"
  gpg --batch --quiet --pinentry-mode loopback \
      --passphrase-file ~/.config/mara/backup-pass -o "$out" -d "$f"
done

# 4. Заново войти в Telegram и Gmail (их состояние не бэкапится, см. выше)

# 5. Убедиться, что ядро видит своё
python3 scripts/contextd_reconcile.py --once
```

Строки `blobs` указывают на пути внутри `/srv/mara-blobs`, поэтому
разворачивать нужно именно туда. Другой корень — придётся править колонку
`path`, и это отдельная работа.

## RPO и RTO

RPO задаёт периодичность крона. Предложение для PR планировщика: **раз в
сутки**, значит потерять можно записи не старше суток. Ежечасно смысла мало
— аудио уезжает зеркалом сразу, а база мелкая; ежечасный прогон дал бы
восемь расшифровок в сутки ради того же результата.

Измерено на doctor 3 сентября 2026 (база 57 КБ, ноль блобов):

| | |
|---|---|
| Бэкап целиком | 0,2 с, архив 2,4 КБ |
| Проверка восстановления | 0,2 с |

Цифры вырастут с аудио: 192 кб/с — это около 1,4 МБ на минуту разговора.
Шифрование зеркала линейно по новым записям, разворачивание — по всему
объёму. Считать RTO по этим цифрам рано; пересмотреть после первой сотни
звонков.

## Известные ограничения

- Ротация по счёту (`--keep 8`), как у волта. Дырка на неделю отпуска
  выносит старые архивы, если крон работал; не работал — не выносит.
- Зеркало аудио не удаляет файлы, которых больше нет в таблице `blobs`, —
  только те, что помечены `purged_at`. Строку удалили руками — копия
  останется на носителе.
- Один `gpg` на файл аудио. При десятках записей в сутки это копейки; на
  порядок больше — шифровать помесячным таром.
