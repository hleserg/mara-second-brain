# Контекст-брокер: Мара знает до tool call

Спека 2 из шести по ТЗ «Mara Ambient Memory» (§15, §22 пункт 4).
Спека 1 (ядро приёма звонков) — `2026-09-02-ambient-memory-design.md`.

## Задача

Мара сейчас узнаёт про обязательства только если сходит в basic-memory. То есть
не узнаёт: она не ищет то, о чём не подозревает. ТЗ §15 требует, чтобы открытые
обязательства и сроки были у неё перед глазами **до** первого вызова инструмента.

Наивное решение — дописать их в `SOUL.md` — ТЗ прямо запрещает: «Убрать
необходимость постоянно переписывать огромный SOUL.md и инвалидировать prompt
cache ради каждого изменения статуса». Каждый звонок меняет список обязательств;
каждое изменение `SOUL.md` рвёт префиксный кэш у провайдера на всех живых
сессиях.

## Решение в одну строчку

Стабильное остаётся в `SOUL.md` и кэшируется. Изменчивое — открытые
обязательства — едет отдельным пакетом через хук `pre_llm_call`, который Hermes
подклеивает **к сообщению пользователя, а не к системному промпту**.

Проверено в `agent/turn_context.py:1313-1365`: возврат хука (`str` или
`{"context": str}`) конкатенируется в user message. Префикс системного промпта
остаётся байт-в-байт тем же, кэш жив. Это ровно то, чего просит ТЗ.

## Что НЕ делаем и почему

ТЗ §15 перечисляет раскладку «например»: `core.md`, `now.md`, `aliases.json`,
`manifest.json`, `people/*.md`, `projects/*.md`. Три из них уже существуют под
другими именами, и дублировать их — платить токенами каждый ход за то, что
модель уже прочитала:

| Из ТЗ | Что вместо | Почему |
|---|---|---|
| `core.md` | блок `mara-brief.py` в `SOUL.md` | Имена проектов и людей меняются раз в недели. Стабильное должно жить в кэшируемом префиксе, а не ехать каждый ход. Это вторая ветка выбора из ТЗ §15: «либо уменьшить до compact aliases/core, либо превратить в generator» — берём первую. |
| `aliases.json` | `_system/entity-index.json` | Уже собирается `entity-index.py`, уже содержит `canonical`/`aliases`/`type`/`title` по 53 сущностям. Второй файл того же смысла — вторая правда. |
| `people/*.md`, `projects/*.md` | — | Пакет по сущности нужен, когда `now.md` не влезает в бюджет. Он влезает: 2500 байт это ~40 обязательств. Появится третий десяток — вернёмся, и `entity-index.json` для резолва алиасов уже лежит. |

Остаются `now.md` и `manifest.json`. Это и есть контекст-брокер.

## Граница «в облако»

Тут единственное место, где спека сознательно ослабляет правило, и это надо
назвать вслух.

Каждая карточка обязательства несёт `sensitive: true, cloud_allowed: false`.
`mara-brief.py` такие карточки пропускает целиком. Если `now.md` унаследует то
же правило, файл будет пустой и критерий приёмки 6 не выполнится никогда.

ТЗ §15 разрешает выход: «Raw transcript/email/message **никогда** не инжектить
напрямую. Только normalized/distilled context pack». Значит наружу едет
дистиллят, и состав дистиллята — это whitelist полей, а не «всё, кроме
запрещённого»:

**Едет:** `title` (формулировка задачи), `due`, `status`, `promised_to`, `origin`.

**Не едет никогда:** тело карточки, `evidence`, спаны, цитаты,
`deadline_phrase` (это дословная фраза из разговора), `confidence`, любая
строка, на которую срабатывает `mara_brief.контакт()`.

`promised_to` проходит через `контакт()` обязательно: карточку человека заводит
журнал звонков, и если контакта нет в книге, там окажется номер телефона.

Whitelist, а не blacklist: новое поле в карточке по умолчанию никуда не едет.

`_system/context/now.md` попадает в git волта, в R2 и в индекс Copilot — как
`_system/mara-brief.md` сегодня. Нового там нет: сами карточки `kb/commitments/`
уже лежат в волте. Исключения Copilot для `kb/commitments` уже записаны в
`docs/USER-MANUAL-STEPS.md`; добавляется `_system/context`.

## Устройство

```
doctor                                          mac-mini
──────                                          ────────
kb/commitments/*.md
   │ context_pack.build_now()   (после каждого звонка + раз в сутки)
   ▼
_system/context/now.md ──► contextd GET /v1/context/bootstrap
   + manifest.json                    ▲
                                      │ http://100.64.0.1:8788 (relay -L)
                                      │
                        плагин ~/.hermes/plugins/mara-context
                                      │ pre_llm_call
                                      ▼

```

### `scripts/context_pack.py` (doctor)

Один модуль — один писатель файла, независимо от того, кто его позвал.

- `собрать(vault) -> (text, items)` — обходит `kb/commitments/*.md`, берёт
  `status` из (`proposed`, `open`), применяет whitelist, сортирует по `due`
  (без срока — в конец), режет по `MAX_BYTES = 2500`.
- `build_now(vault) -> sha256` — пишет `now.md` и `manifest.json` атомарно
  (tmp + rename) под замком волта.
- `--self-check`.

Переиспользует `frontmatter()` и `контакт()` из `mara-brief.py`. Ничего своего
для разбора фронтматтера не пишет: парсер в репо один, регэкспный, и вторая его
копия разойдётся с первой.

Зовётся из `call_project.run()` в конце и из крона рядом с `mara-brief`.

### `contextd`: `GET /v1/context/bootstrap`

К существующему ответу добавляется `"now"`:

```json
{"now": {"text": "...", "sha256": "…", "generated": "2026-09-02T…"},
 "last_digest": {...}, "queue": 0, "pipeline_version": 1}
```

Читается из файла на каждый запрос: файл маленький, а лишний кэш — лишняя
причина отдать вчерашнее. Файла нет — `"now": null`, не ошибка.

### Плагин `mara-context` (mac)

Раскладка как у `mask-ear`: `plugin.yaml` (только метаданные, хуки в нём не
объявляются) + `__init__.py` с `def register(ctx)`.

Три вещи, без которых плагин вреден:

1. **Свой таймаут 2 с.** Хук в Hermes ограничен 30 с и fail-open. Лежащий
   doctor или упавший relay добавили бы 30 секунд к каждой реплике Мары —
   это хуже, чем отсутствие контекста.
2. **Кэш последнего удачного ответа, TTL 60 с.** Иначе каждый ход — поход по
   сети.
3. **Инжект по изменению, а не каждый ход.** Плагин помнит
   `{session_id: последняя_отданная_sha}`. Совпало — возвращает пустую строку.
   `is_first_turn` для этого не годится: телеграм-сессия живёт сутками и
   первый ход в ней бывает раз в неделю.

Исключение наружу не выпускается никогда: любая ошибка — пустая строка и
строка в лог.

Токен устройства — из `ctx.get_config("token")` или окружения, в репозиторий не
попадает (как `session_key` у `mask-ear`).

### Что будет во второй нарезке

Инструмент `mara_correction`: Серёга отвечает на дайджест «это тоже задача, срок
пятница», Мара зовёт инструмент, плагин постит `kind: correction` в
`/v1/ingest/event`, contextd применяет синхронно через
`call_project.apply_correction()` — тот же модуль, что пишет карточки, один
писатель. Семантика `supersedes`, а не перезапись.

Регистрировать надо в toolset `hermes-telegram`: `platform_toolsets.telegram`
в конфиге ограничивает `enabled_toolsets` этим списком, инструмент в новом
toolset агент на телеграме просто не увидит.

Вторая нарезка не начинается, пока первая не развёрнута и пока не увиден хотя бы
один ход с инжектом.

## Тесты

`tests/test_context_pack.py`:

- открытое обязательство попадает в `now.md`, закрытое — нет;
- срок печатается, порядок по сроку, «без срока» в конце;
- **тело карточки в `now.md` не попадает** (карточка с телом и цитатой →
  в пакете есть заголовок и срок, ни одной строки тела нет);
- `deadline_phrase` не попадает;
- номер в `promised_to` не попадает;
- пакет не длиннее `MAX_BYTES`;
- пустой набор даёт пустой файл, а не падение;
- повторный запуск не оставляет `.tmp`.

`tests/test_cloud_boundary.py` — расширяется тем же случаем с телом карточки,
чтобы граница проверялась там, где её будут искать.

Плагин проверяется своим `_demo()` без Hermes, как `mask-ear`: подложный ctx,
подложный HTTP, три случая — свежая sha инжектится, та же sha молчит, сеть
лежит и хук возвращает пустую строку за отведённые 2 секунды.
