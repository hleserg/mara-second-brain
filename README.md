# mara-second-brain

Инфраструктура «второго мозга»: markdown-волт, который читается человеком в Obsidian,
служит памятью ассистенту Маре и даёт агентам контекст проектов.

**Это репозиторий инструментов, а не волта.** Волт — отдельный git-репозиторий на `doctor`
в `/srv/vault`, пушится только в bare-зеркало `/srv/backup/vault.git`. В GitHub он не уезжает
никогда: там `sensitive: true` и личный дневник.

ТЗ: [`docs/TZ.md`](docs/TZ.md).

## Топология

| Что | Где |
|---|---|
| Волт (source of truth) | `doctor:/srv/vault` |
| Bare-зеркало | `doctor:/srv/backup/vault.git` |
| Транспорт на устройства | Cloudflare R2, бакет `mara-vault` (Remotely Save / rclone) |
| Obsidian | Mac mini, Windows, телефон |
| Мара (Hermes) | Mac mini M1 |
| Тяжёлые батчи | GTR (WSL, GPU), по требованию |
| `beta-pi` | только разработка. Ничто в рантайме на неё не завязано (§13.6) |

## Установка на doctor

```bash
git clone git@github.com:hleserg/mara-second-brain.git ~/mara-second-brain
~/mara-second-brain/install/stage0-doctor.sh          # волт, git, зеркало, крон
~/mara-second-brain/install/basic-memory-doctor.sh    # Basic Memory + MCP
~/mara-second-brain/scripts/stage0-selftest.sh        # приёмка
```

Оба установщика идемпотентны. Креды R2 живут в `~/.config/rclone/rclone.conf`
на doctor и в репозиторий не попадают (ТЗ §11).

## Что крутится на doctor

`install/install-cron.sh`. Без аргументов скрипт только показывает
расхождение живого crontab с репозиторием и ничего не меняет, `--apply`
ставит, сделав копию текущего crontab в `~/.local/state/mara/`. Чужие
строки на doctor он не трогает. Правки через `crontab -e` затрёт следующая
установка — менять расписание надо в файле.

### Почему обязательства не в SOUL.md

Стабильное — имена проектов, людей, машин — живёт в системном промпте: оно
меняется раз в недели, и провайдер кэширует префикс промпта между ходами.
Открытые обязательства меняются с каждым звонком. Дописать их туда же значило бы
рвать кэш всем живым сессиям при каждом звонке, а ТЗ §15 это прямо запрещает.

Поэтому изменчивая часть едет отдельно: `scripts/context_pack.py` собирает
`_system/context/now.md`, contextd отдаёт его по `/v1/context/bootstrap`, а
плагин `mara-context` на маке подкладывает в ход хуком `pre_llm_call` — Hermes
клеит его возврат к сообщению хозяина, а не к системному промпту.

Карточки обязательств несут `cloud_allowed: false`, а пакет уезжает провайдеру.
Наружу идёт whitelist из пяти полей фронтматтера (`title`, `due`, `status`,
`promised_to`, `origin`), а не «всё, кроме запрещённого»: новое поле в карточке
по умолчанию никуда не поедет. Тело, цитаты, спаны и дословные фразы о сроке
остаются в волте. Проверяется в `tests/test_cloud_boundary.py`.

Читатель берёт из файла только то, что между маркерами `<!-- mara:now -->`:
Basic Memory синкает волт и дописывает свой фронтматтер в каждый `.md`, включая
этот, и провайдеру он не нужен.

Плагин молчит, пока список не изменился, и отвечает за свои две секунды: хук в
Hermes ограничен тридцатью и fail-open, так что лежащий doctor иначе добавлял бы
полминуты к каждой реплике Мары.

### Где лежат записи звонков

Не в волте. `/srv/mara-blobs` на doctor, права 0700, дерево `calls/ГГГГ/ММ/`,
имя файла — sha256 содержимого. Это вне волта осознанно: волт синкается в R2 и
лежит в git, а запись личного разговора не должна попасть ни туда, ни туда.
Поэтому в `config/r2-filters.txt` блобов нет и быть не должно — исключать
нечего, они просто не в том дереве. В волт из звонка попадают только карточка
разговора и карточки обязательств, с `sensitive: true` и `cloud_allowed: false`.

Аудио удаляется через 90 дней, манифест в `/srv/mara-blobs/manifests/` остаётся
навсегда: по нему видно, что звонок был и куда делась запись.

Ручные шаги владельца — `docs/USER-MANUAL-STEPS.md`.

## Ingest сессий (этап 2)

```
Claude Code ──SessionEnd-хук──┐
                              ├─► спул ~/.local/state/mara/spool ──rsync──► волт
Codex ────────крон *:10───────┘        (он же очередь ретраев)
                                                │
                              kb/sessions/<id>.md + _system/queue/<id>.json
                                                │
                              крон *:40  queue-worker → редакция §8.3 → OpenRouter
                                                │
                              то же имя файла, distilled: true
```

**Карточка появляется сразу, без всякой LLM.** Заголовок, дата события, каталог,
счётчики, ссылка на сырьё — этого хватает, чтобы сессия нашлась поиском, и это
работает при мёртвой сети (§8.4, слой 2). Смысл сессии дописывает дистиллятор
позже, перезаписывая тело той же карточки.

| Машина | Что поставить |
|---|---|
| любая с Claude Code | `hooks/claude-session-end.sh` в `SessionEnd` в `~/.claude/settings.json` |
| любая с Claude Code | одна строка в statusline и `scripts/claude-usage-ship.py` кроном `*/5` — учёт лимитов, [`docs/claude-usage.md`](docs/claude-usage.md) |
| любая с Codex | `scripts/codex-mirror.sh` по расписанию (у Codex хуков нет) |
| beta-pi, мак | systemd/launchd туннель `ssh -L 127.0.0.1:8787:127.0.0.1:8787 doctor` для MCP |

Клиент шлёт карточку не прямо в волт, а в локальный спул, и уже спул уезжает
`rsync`-ом. Нет сети — карточка лежит в спуле, следующий запуск хука доносит.
`rsync` пишет через временный файл и переименовывает, поэтому автокоммит (`*/15`)
и bisync (`*/5`) не поймают полузаписанный файл.

**Ключ дистиллятора:** `~/.config/mara/env` на doctor, `chmod 600`,
`OPENROUTER_API_KEY=...`. В волт и в репозиторий не попадает (§11). Без ключа
worker не падает, а держит очередь.

## Переезд на бакет `mara-vault` (1-2 сентября) — закрыто

Старый бакет `obsidian-vault` заболел: 14 объектов из 184 перестали
перезаписываться и удаляться — `HTTP 500 InternalError` навсегда, ретраи не
помогают. Что измерено, а не предположено:

| Опыт | Результат |
|---|---|
| Принудительная перезапись всех 184 файлов волта, дважды | оба раза падают **одни и те же 14**, расхождений ноль |
| Здоровый ключ: запись → перезапись через 200 с → удаление | три раза `rc=0` |
| Пробный бакет: 40 объектов, перезапись через 5 мин, удаление | 0 ошибок |

Значит порча привязана к объектам, детерминирована и локальна для бакета —
поэтому переезд, а не ретраи. Волт остался нетронутым: он источник истины (§1),
бакет всего лишь транспорт (§2.1).

**Чем кончилось.** 2 сентября Remotely Save перецелен на всех устройствах,
старый бакет сутки не принимал записи — и удалён целиком. Перед удалением он
слит на doctor в `/srv/backup/r2-obsidian-vault-2026-09-02/` (207 объектов,
113 МБ, `rclone check` — 0 расхождений); там же лежат 59 файлов, которых в
волте нет: копии репозиториев, вычищенные на шаге 3 реструктуризации, и
пробные ключи селфтеста. `rclone purge` снёс и залипшие 14 — к тому моменту
Cloudflare их отпустил. Вместе с бакетом удалены `scripts/r2-legacy-pull.sh`,
`scripts/r2-retry-orphans.sh` и их конфиги; `stage0-selftest.sh` и
`purge-from-vault.sh` переведены на `mara-vault`.

Единственный оставшийся бакет — `mara-vault`. `obsidian-vault` в
`config/git-repos.txt` — это репозиторий на GitHub, не бакет, и он живой.

## Мара (этап 3)

```
мак: Hermes gateway ──MCP──► 127.0.0.1:8787 ──обратный ssh-туннель──► doctor
                                                     Basic Memory (проект vault)
doctor: hermes-ingest ──ssh──► ~/.hermes/state.db ──► raw/hermes/ + kb/sessions/
        mara-watchdog ──ssh──► ticker_last_success ──► gateway restart, если молчит
        mara-brief ──ssh──► SOUL.md: блок «Что ты уже знаешь о Серёге» из entities/
мак: cron Мары 9:00 ──script-only──► ssh doctor daily-summary.py ──► телеграм
```

Ставится с doctor: `install/mara-mac.sh`. Направление туннеля выбрано не от
красоты: фоновая служба на маке — это launchd в GUI-домене, а туда из
ssh-сессии не достучаться (`launchctl bootstrap` и `kickstart` отлетают с
«Domain does not support specified action»). systemd на doctor управляется как
угодно, поэтому туннель держит он, обратным форвардом `-R`. Порт садится на
loopback мака, наружу не торчит (§11).

**Тексты §7.1–§7.3 живут в `~/.hermes/SOUL.md`** — это единственный файл
персоны, который gateway читает (`HERMES_HOME`). Копия в `~/Obsidian/Knowledge/`
осталась с апреля и никем не грузится. Блок поведения врезан к «Чего Мара НЕ
делает», политика захвата — в конец: последнее в промпте весит больше.

**«Я знаю Серёгу».** Имена проектов, людей, мест и инструментов Мара не
ищет, а помнит: `scripts/mara-brief.py` раз в сутки собирает из фронтматтера и
первого абзаца карточек `entities/` блок между `<!-- mara:brief -->` и
`<!-- /mara:brief -->` и врезает его в `SOUL.md` перед «Когда он изливает
душу». Карточки с `sensitive: true` в блок не идут — SOUL.md уезжает провайдеру
модели (§11). Копия блока лежит в `_system/mara-brief.md`, чтобы было видно, что
именно она «знает». Потолок блока 14 КБ: он едет в каждый ход. Системный
промпт Hermes собирает один раз на сессию и хранит в `state.db` по хэшу, рестарт
gateway его не обновляет (см. decisions, 2 сентября). Поэтому после записи
блока скрипт делает то же, что `/model`: обнуляет `system_prompt_hash` живым
телеграм-сессиям, и на следующей реплике промпт собирается заново с историей.
Блок без даты — хэш сбрасывается только когда карточки реально изменились.
Правишь `SOUL.md` руками — сбрось хэш тем же `UPDATE` или `/model` в телеграме.
Копии до первой врезки: `SOUL.md.bak-before-brief`, `state.db.bak-before-brief`.

**Разговоры с Марой не уезжают в облако.** Карточка и сырьё делаются, задача в
очередь не ставится: это не рабочая сессия, а дневник, настроение и третьи лица
(§7.2, §8.3.3). Решить иначе — `hermes-ingest.py --to-cloud`.

**В волт едут только разговоры с человеком.** У сессии в `state.db` есть
`source`: `telegram` — Серёга пишет, `cli` — кто-то сидит за маком, `cron` —
Мара сама себе по расписанию, `subagent` — делегирование. Три последних
пропускаются (`MARA_SKIP_SOURCES`), иначе каждое напоминание становится
карточкой сессии и лезет в дневную сводку. `cli` в списке потому, что мак
стоит без монитора и консолью туда ходит обслуживание, а не владелец.

**Сессия у Мары не кончается** — `session_reset` выключен, разговоры
группируются по пользователю, и телеграмный `sid` живёт месяцами. Поэтому
сырьё переписывается каждый прогон, а карточка заводится один раз, и её
`occurred` — дата первого снимка, а не сегодняшняя.

**У Мары не все инструменты Basic Memory.** `delete_note`, `move_note`,
`delete_project`, `create_memory_project` убраны: волт не её, она в нём пишет,
а не убирает. Вместе с ними — облачные `cloud_info`/`list_workspaces` (§13.7)
и `release_notes` со `schema_*` как шум. Список чёрный, в
`mcp_servers.basic-memory.tools.exclude` на маке: новые читающие инструменты
подхватятся сами.

## Бэкапы (§12)

Копий три, но защищают они от разного. `/srv/vault` и bare-зеркало
`/srv/backup/vault.git` лежат на одном физическом диске: он умрёт — умрут обе.
R2 — синк, а не бэкап: удаление и порча уезжают туда за пять минут и там же
затирают хорошее. Поэтому раз в неделю `scripts/vault-backup.sh` делает
`git bundle --all` из зеркала, шифрует его gpg-паролем (AES256, симметрично) и
кладёт на два носителя: внешний диск `/mnt/backup/mara` и шару соседней машины
`/mnt/win-backups/mara`. Держим 8 штук, это ~1 ГБ на носитель. Шара может быть
отключена — прогон это переживает и пишет в лог, валится он только если не
записался ни один носитель.

Шифруем, потому что в git лежит `raw/` — сырьё разговоров с Марой и рабочие
логи. На сетевую шару соседней машины оно в открытом виде не поедет.

**Парольная фраза** лежит на doctor (`~/.config/mara/backup-pass`, 600) и
копией в Bitwarden у владельца. Копия обязательна: фраза живёт на той же
машине, от смерти которой бандлы защищают, — без неё они макулатура.

`scripts/vault-restore-test.sh` разворачивает свежий бандл: расшифровка,
`git bundle verify`, клон, сверка родословной с зеркалом (HEAD бандла обязан
быть в зеркале — сравнивать HEAD с HEAD нельзя, недельный бандл отстаёт по
определению), счёт заметок. Прогнан на обоих носителях 2026-09-01: 621 заметка,
всё разворачивается.

Вычистка секрета из истории (`scripts/purge-from-vault.sh`) теперь сносит и
старые бандлы: в них лежит прежняя история целиком, и без этого §11 тихо
ломался бы — секрет остался бы на двух носителях, просто под шифром.

## Автосвязи (§5.4, §5.5)

Дистиллятор перечисляет людей и проекты простым текстом и правильно делает:
§5.3 запрещает ему линковать то, чего нет в реестре, иначе он придумывает
заметки. Но дальше этого не шёл никто, и в волте лежали 484 карточки с
текстовыми именами и ноль рёбер между ними.

`scripts/entity-link.py` — второй проход §5.4. Детерминированный, без модели:
сверка со списком, а не догадка. Собирает строки `Люди:`/`Проекты:` из карточек,
склеивает написания (регистр, `ё`, дефисы: `Attadipa` и `attadipa` — одно),
заводит недостающие сущности и переписывает те же строки ссылками на канон —
`[[sergey|Сергей]]`, а не `[[Сергей]]`: голый алиас Obsidian не резолвит.

Что он **не** делает:

- **людей не заводит вовсе.** Живой человек в волте один — владелец. Остальные
  «люди» из git-логов это `dependabot[bot]`, `claude[bot]` и прочие подписи
  ботов (отбрасываются) да имена ассистентов — Claude, Cursor Agent, Alfred.
  Карточка на каждого дала бы граф из мусора. Владелец разбирает их сам по
  `_system/entity-review.md`, а то, что заводить не надо, вписывает в
  `_system/entity-ignore.txt` — иначе отвергнутое всплывает в отчёте вечно
  и в нём тонет новое;
- **похожее не сливает.** §5.5 требует очередь на подтверждение, и это не
  перестраховка: `mara`, `mara-arena` и `mara-second-brain` — три разных
  репозитория, а не опечатки друг друга. Скрипт только предлагает;
- **проекты заводит от трёх упоминаний.** Ниже порога граф зарастает узлами
  вроде `LVGL` и `ESP-IDF`, мелькнувшими в одном коммите, — ровно та каша,
  от которой §5 и защищается.

Реестр завёлся за один разбор с владельцем: 30 репозиториев из
`config/git-repos.txt` (список репозиториев — единственный честный список
проектов, его не надо угадывать), три зонтичные темы над ними, семь ассистентов и четыре платы в
`tools/`, пять машин в `places/`. Заодно проход догоняет поле `project:` в
шапке: 446 git-карточек писались до того, как завелись сущности, и держали его
текстом.

Одна карточка заведена руками — `entities/people/sergey.md`. Владелец приезжает
в карточки восемью написаниями (имя кириллицей и латиницей, фамилия, ник,
сокращения): дистиллятор берёт подпись из того текста, что ему дали. Все они
сведены алиасами, и ~450 упоминаний стали одним узлом, а не восемью.

Линковка живёт в общей `linkify()` (`vault_common.py`) и вызывается из двух
мест: дистиллятор линкует карточку в момент записи, ночной прогон догоняет
старые, когда сущность завелась позже. Иначе очередь дистилляции возвращала бы
уже связанные карточки обратно текстом.

## Дневные страницы (§9)

Карточек больше тысячи, и лежат они россыпью по `kb/`. `scripts/daily-page.py`
собирает `daily/YYYY-MM-DD.md` — оглавление дня: что коммитил, о чём были
разговоры, какие заметки завелись. Ссылками на карточки, без пересказа:
пересказывает своими словами `daily-summary.py`, и тот уезжает в телеграм.

В тот же файл Мара дописывает дневник (§7.2), поэтому машинный кусок живёт
между маркерами `<!-- mara:auto -->` и в самом верху — её `append` всегда
падает ниже и переживает пересборку. Шапку скрипт заводит один раз и больше не
трогает: `sensitive` в ней могла стать `true` из-за дневника, и затирать это
нельзя. `daily-summary.py` этот блок вырезает — те же карточки он уже
пересказал, а ссылки в телеграме мусор.

Дата берётся из `occurred`, а если её нет (ручные заметки Мары её не ставят) —
из дня `created`. Бэкфилл прогнан: 363 дня, самый ранний за 2022-04-11.

Крон пересобирает **все** дни, а не вчерашний. Карточки приезжают задним
числом (сессия за 27 июля разобралась 1 сентября), дистилляция очереди в 3:40
может не успеть до 3:55, а старые проекты становятся ссылками только когда
сущность заведут. Построить день один раз значит навсегда потерять всё, что
приехало позже. Полная пересборка — секунда, и она ничего не переписывает,
если ничего не изменилось.

Одна засада: Basic Memory переписывает файл следом и срезает последний перевод
строки. Побайтовое сравнение из-за этого переписывало все 363 страницы каждый
прогон, поэтому хвостовые переводы при сравнении не считаются (§13.8).

## Отступления от ТЗ и почему

**Близость эмбеддингов (§5.5) не считается.** ТЗ предлагает сливать кандидатов
по косинусу > 0.85. На именах из двух слов эмбеддинг — шум, а лезть за моделью
в venv Basic Memory значит привязаться к его внутренностям. Реальные дубли в
данных другие: регистр, дефис против подчёркивания, опечатка. Первые два
склеиваются нормализацией, третий предлагается через `difflib`. Load-bearing
половина §5.5 — «в очередь на подтверждение, не сливать автоматически» —
соблюдена буквально.

- **Квартальный тест восстановления не переиндексирует Basic Memory.** §12
  просит в тесте ещё и переиндексировать BM из markdown и проверить поиск.
  Переиндексация 621 заметки с эмбеддингами идёт больше десяти минут и требует
  своего окружения, а проверяет ровно то же самое — что markdown на месте.
  Кроновый тест остаётся файловым, а переиндексацию из восстановленного клона
  прогнали руками один раз при заводке.

- **Плагин Basic Memory не ставился, вместо него MCP.** §7.4 ставит плагин
  первым путём, а MCP вторым, но у Hermes есть свой `hermes mcp add --url`, и
  это ровно тот способ, которым к 8787 уже ходят Claude Code и Codex. Обход
  с `manifest_version: 2` и симлинком не понадобился. Оговорка §7.4 «MCP
  недоступен в cron-сессиях» ничего не ломает: регулярные задачи ТЗ и так
  требует делать script-only cron-ом.
- **`systemd_watchdog_seconds: 120` не выставлен.** Это sd_notify; на маке
  launchd, а не systemd, и ключ там пустой звук. Ту же дыру закрывает
  `mara-watchdog.sh` снаружи, с doctor.
- **Дневная сводка без встреч и мест.** §10 требует их в приёмке этапа 3, но
  они приходят из почты и календаря (§6.6), а этап 5 закрыт решением
  владельца. В сводке — коммиты, сессии и дневник.
- **Сводку пишет модель, хотя cron script-only.** Задумано было собрать её
  механически из заголовков карточек, без облака. Так и было сделано — и
  оказалось нечитаемо: заголовок карточки написан для поиска в волте, а не
  для чтения за завтраком. Теперь карточки за день уходят одним куском в
  модель и возвращаются человеческим текстом. Cron по-прежнему script-only:
  LLM зовёт сам скрипт на doctor, а не cron-сессия Мары. Секретные карточки
  (§8.3.3) и дневник в облако не едут; нет ключа — печатается прежняя
  механика с оговоркой почему.
- **Очередь не синкается в R2.** `_system/queue/` — машинное состояние
  doctor. Воркер снимает до двухсот задач за прогон, а у bisync
  `--max-delete 25`: каждый разбор очереди валил синк, и заодно возвращал из
  бакета то, что мы только что удалили.
- **Remotely Save → rclone bisync.** Remotely Save это GUI-плагин Obsidian,
  на headless doctor его не запустить. Тот же бакет, исключения из §2.1
  в `config/r2-filters.txt`.
- **MCP на 8787, а не 8765.** 8765 на doctor занят docker-proxy контейнера
  `caddy-letheclaw`.
- **Свой rclone в `/opt/rclone`.** Системный 1.60 (2022), его `bisync`
  разваливается. Общий бинарь не трогаем — на нём чужие бэкапы.
- **Эмбеддинги Basic Memory через Ollama, не fastembed.** У fastembed из
  коробки `bge-small-en-v1.5` — английская модель на русско-английском волте.
  Провайдер переключён на litellm → `ollama/bge-m3`, 1024 измерения.
  Проверено: русский запрос «как настроить mqtt для умного дома» находит
  английские доки iot-stack.
- **Вьюхи Bases лежат в `views/`.** В §3 такой папки нет, а `_system/` — это
  служебное состояние, не пользовательский слой.
- **Структура §3 добавлена рядом с существующими папками волта**
  (`atman/`, `MeshCore/`, `Умный дом/`…), а не вместо них.
- **`Stop` как страховка не подключён.** §6.1 предлагает его вторым хуком, но
  `Stop` срабатывает каждый ход — это ssh-запись на каждую реплику. Ту же дыру
  (краш, сессия с мака, долгий оффлайн, вообще отсутствие хуков у Codex)
  закрывает `scripts/sessions-backfill.sh` на doctor: раз в час проходит по
  свежему сырью и делает недостающие карточки. Один сборщик вместо двух.
- **Имена людей не вычищаются перед отправкой в облако.** §8.3 требует
  PII-редакции, но §5 и §7 требуют, чтобы дистиллятор доставал людей и заводил
  карточки в `entities/people/`. Вырезав `PERSON`, мы ломаем этап 4. Режем то,
  что реально опасно: ключи, токены, приватные ключи, почту, телефоны, карты,
  IP. Список в `scripts/redact.py`, `PII_ENTITIES` — правится одной строкой.
- **Разовый прогон всей истории сделан** (решение владельца, 1 сентября):
  `DAYS=99999 scripts/sessions-backfill.sh` — карточек стало 551 против 45.
  По расписанию скрипт по-прежнему смотрит только 3 суток.
- **Шаг 3 уборки волта переписан.** Прежний вывод «байт-в-байт не совпадает ни
  один файл» мерил фронтматтер Basic Memory и переписанные ` ```text `, а
  сравнивал с клоном репы, отставшим на 933 коммита. По-честному 45 файлов из
  64 — чистые копии репы. Разбор — `docs/vault-cleanup-step3.md`, считалка —
  `scripts/vault-vs-repo.py`.
- **Мак в этап 2 не входит: там нет Claude Code.** Проверено по ssh — ни
  бинаря, ни в PATH. Все 508 транскриптов оттуда уже на doctor, сверено
  пофайлово. Ставить хук не на что.

## Obsidian на устройствах

Набор плагинов один на все устройства и едет через R2 вместе с настройками:
`remotely-save`, `copilot`, `omnisearch`, `calendar`. Dataview, Tasks, Excalidraw,
PDF++, Smart Connections и Smart Lookup сняты 2 сентября: в 1503 заметках не было
ни одного запроса Dataview и Tasks, один рисунок и один PDF, а семантический
поиск дублировал Copilot тремя индексами на телефоне. Запросы — только Bases,
`views/*.base` (§9).

Настройки едут через Remotely Save, `Sync Config Dir (experimental)` включён на
каждом устройстве. Без этих правил оно ломается:

- **Правишь на одном устройстве, остальные только принимают.** RS берёт файл с
  более свежим mtime. Первичная настройка «на всех руками» кончилась тем, что
  телефон, синкнувшийся последним, затёр `app.json` пустым, и исключение поиска
  `Claude Usage/_data` пришлось возвращать с doctor.
- Приехали настройки — `Reload app without saving`: до перезапуска Obsidian
  живёт старым списком плагинов.
- В `Regex Of Paths To Ignore` на каждом устройстве три строки:
  `\.obsidian/plugins/copilot/data`, `\.obsidian/plugins/remotely-save/data`,
  `\.obsidian/copilot-index-.*`. Первые две держат ключи и доступ к R2 дома
  (в исходнике RS игнор проверяется раньше правила «папка конфига синкается»),
  третья — 85 МБ индекса. `config/r2-filters.txt` устройствами не управляет,
  он только про doctor: устройства пишут в бакет напрямую.
- `workspace.json` RS не синкает сам, а `workspace-mobile.json` синкает. На
  телефоне можно добавить `\.obsidian/workspace.*`, иначе 13 КБ раскладки ездят
  каждый цикл. Не критично.

Точка входа в волт — `Главная.md`, закладка на неё в Bookmarks едет со всеми:
вчерашний срез из `views/Что я делал.base`, все сущности из
`views/Сущности.base`, ссылки на `kb/`, отчёты Claude Usage и линтеров. Ядро
`daily-notes` смотрит в `daily/` с форматом `YYYY-MM-DD`, поэтому Calendar
открывает страницы дня, которые собирает `daily-page.py`; чужой файл он
дополняет своим блоком, не перезаписывает.
