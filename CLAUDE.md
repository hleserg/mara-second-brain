# Мара — заметка для агента

Нормативные документы, читать перед работой, а не этот файл:

- `docs/CONTRIBUTING.md` — роли, PR-only, гейты, ограничения субагентов.
- `docs/PLAN-to-done.md` — маршрут: следующая незакрытая карточка берётся
  оттуда (§10), PR ставит галочку в том же PR и правит §7
  `docs/current-state-audit.md`.
- `docs/TZ-master.md` — требования; `docs/RUNBOOK-deploy.md` — выкат.

## Что знать про код

- Python 3.12 на doctor, только stdlib, тестовый фреймворк — `unittest`.
  Фреймворков и зависимостей не заводить.
- Язык кода и документов — русский: комментарии, докстринги, имена тестов,
  часть идентификаторов. Новый код пишется в стиле файла, в котором он лежит.
- Репозиторий публичный (Г7): ни имени владельца, ни логинов, ни адресов
  домашней сети, ни номеров телефонов — ни в коде, ни в тестах, ни в теле PR.
- Схема реестра меняется только нумерованной миграцией в
  `scripts/mara_ingest.py` (`МИГРАЦИИ`, `ОТКАТЫ`); `SCHEMA` заморожена как
  базлайн. Перестройка живой таблицы — гейт Г4, не делать без разрешения.
- Числа в документах — только из команд, и команда называется (правило 16
  плана). Номера строк в ссылках гниют: называть функции, не строки.

## Гейт

```
SKIP_ANDROID=1 bash scripts/run-tests.sh      # ≈1,5 мин: unittest + все --self-check + bash -n
python3 -m unittest tests.test_X -v           # один модуль
python3 scripts/X.py --self-check             # одна самопроверка
```

Счёт тестов — строка `Ran N tests` и `OK`, самопроверок — `grep -c "^ok  "`.
Результаты прогона пишутся в тело PR числами (шаблон §19).

## Облачная сессия

`.claude/hooks/session-start.sh` выставляет переменные гейта (как в
`.github/workflows/tests.yml`) и `SKIP_ANDROID=1`. Kotlin-работа (`android/`,
гейт Г2) здесь не собирается: сетевая политика окружения закрывает
`dl.google.com`, откуда берётся Android Gradle Plugin — проверять Kotlin
через job `kotlin` в CI. Доступа к doctor, волту и секретам из облака нет;
задачи с пометкой «владелец» и «агент+гейт» отсюда не выполняются.
